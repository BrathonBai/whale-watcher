## 0. 一句话结论

**技术链路已经"能演"，产品化只完成约两成：这台设备现在最准确的定位是「一块跑通了陪伴链路的开发板」，不是「能卖的桌面陪伴大肥鱼」。**

但和常见原型不同，**底子比想象扎实**：协议契约、Opus 下行、412 圆屏动画、触摸/旋钮/音效、桥的 10 套回归、人格层代码都是真做出来的资产（分审计 A §5 列了 15 条、B §4 列了 15 条）。真正缺的不是功能，是**消费品化的五件事**：

1. **出厂能力**（配网/身份/OTA/回滚/电源策略）——5 件基本是空的；
2. **可安装**（用户要自己装 DSH + Python + 1.23 GB 模型 + 自备 API key）——普通用户装不了；
3. **陪伴行为**（存在感/主动性/记忆）——《伙伴形态-可行性》写下的 12 条行为，端到端**做到 0 条**；
4. **可卖**（产品定义 3 套并存、4 个名字、IP 无授权、无成本/定价）；
5. **可体验**（首音约 7 s、不能打断、断网无屏显、没有恢复出厂/救砖路径）。

用户旅程 8 环里，普通用户今天能独立走通的只有 **「上电」和「本地摸头」**；配网、绑定、首聊、售后四环全断（分审计 C §②）。

## 3. 「陪伴」到底差在哪：12 条行为逐条对照

依据 [`伙伴形态-可行性.md`](伙伴形态-可行性.md) §4（这是产品自己定义的第一版验收规格）。

| # | 行为 | 端到端状态 | 卡在哪 |
|---|---|---|---|
| 1 | 有人进入视野 → 抬眼看一眼 | ❌ 未做 | 摄像头按需快门；Himax 人检测未接入 |
| 2 | 你靠近/盯着它 → 瞳孔对齐、括号张开 | ❌ 未做 | 无连续视觉输入（光瞳只在浏览器原型里） |
| 3 | 叫它名字 → 睁眼 + 聆听态 | ❌ 未做 | 无唤醒词；录音靠按键 |
| 4 | 无事 30 分钟 → 主动说一句 | ❌ 未做 | persona 未加载；桥无定时器 |
| 5 | "让我看看" → 拍照 → VLM → 念一句 | 🟡 零件在、闭环未验 | `device_shot` 工具与相机链路在，但 `brain=session` 建会话失败（工具不可用）；未做真实对话验证 |
| 6 | 有人停留 10 s → 记事件，回来汇报 | ❌ 未做 | 无人检测；无事件记忆 |
| 7 | 隔天提起你提过的事 | ❌ 未做 | 无跨天记忆/摘要 |
| 8 | 被夸/被骂 → 情绪态变化 | 🟡 半条 | `guessMood()` 只从文本猜 8 个 mood，不持久、无心情/精力 |
| 9 | 无人 20 分钟 → 睡；有人靠近 → 睁眼 | ❌ 未做 | 无存在检测；待机只有动画 |
| 10 | 旋钮设提醒；到点预制音效+一行字 | ❌ 未做 | 菜单只有音量/配网/电量/关机 |
| 11 | "看右边" → 诚实说"我转不了头" | ❌ 未做 | systemPrompt 未写能力边界（还写着"戴在身上"） |
| 12 | Watcher 看到 → Cardputer 显示/震动（双设备） | ❌ 未做 | 单设备单连接 |

**结论：✅0 / 🟡2 / ❌10。**
今天用户实际得到的是：**按键问一句 → 等约 7 秒 → 听一句、看字幕 → 可以摸摸头换动作**。
这比智能音箱多的只有一个"摸头有反应"；比"陪伴"少的正是三根支柱——**存在感（它看见你）、主动性（它先开口）、记忆（它记得你）**。

**首版最小陪伴闭环（建议只做这 4 件，2–3 周）**：
① 触摸/按键"说话"→ 首音 ≤3 s；② 有人靠近 → 抬眼/看你（先用人检测或"摄像头被调用前先抬眼"的替代，不追求完美）；③ 沉默 20 min → 主动一句（接 persona 规则表）；④ 记住 3 条关于用户的事，隔天能提一次。
摸头反馈已经具备，保留即可。

## 4. 三个必须先拍的决策（不可逆或决定路线）

### D1 · 卖什么形态（本周定）

| 选项 | 内容 | 代价 | 适合 |
|---|---|---|---|
| **A（推荐先做）** | 现成 Watcher 整机 + 3D 打印/硅胶包覆支架，标"内测/开发者版"，20–100 台 | 不改模、认证压力小；毛利低（整机成本 ¥500–720） | 验证留存/NPS/价格 |
| B0 | OSHW 外壳改模 + 3D 打印/小批量硅胶，仍 PC 大脑 | 3–6 周结构工作；仍不算量产外壳 | 内测机质感 |
| B | 自研外壳 + 认证 + 云端 + 售后，正式量产 | 8–20 万模具、3–6 个月、认证 5–15 万 | 留存验证通过后 |
| C | B2B 行业交付（展陈/办公陪伴） | 销售驱动、不可复制 | 现金流补充 |

**建议**：先 A（或 A+B0 混用）卖 20 台内测，**验证通过前不开模、不上云端账号体系**。

### D2 · 大脑放哪（本周定方向，首版可先落地）

- **首版（内测）**：把桥从 DSH 里剥出来，做成**一键安装的 Windows 服务/应用**（含 ASR、ffmpeg、配置向导、开机自启、自检），用户不需要 DSH/Python/命令行。TTS 先用 BYO key 或服务端代理，不把 key 下发。
- **量产**：迁云（网关/ASR/TTS/LLM/会话/人格/记忆/调度 + 账号/绑定/OTA/遥测），PC 降级为可选桌面端。
- 两者共用同一套协议与桥业务逻辑，**不要重写契约/降级/音频策略**（分审计 B §4）。

### D3 · 不可逆技术基线（首批投产前必须冻结）

1. **电源形态**：插电为主（去掉电池，或电池只做断电缓冲）还是保留 400 mAh？
2. **Secure Boot / Flash 加密**：是否启用（eFuse 一次性，首批前必须定）。
3. **设备身份规则**：SN 从 eFuse MAC 派生，产线可读 SN 方案。
4. **配网形态**：AP + 手机网页（推荐，成本最低）vs BLE 小程序。
5. **OTA 通道**：局域网 HTTPS（内测）→ 云 OTA（量产）。

这 5 项一旦首批投产就改不动，建议 1 周内出 5 份决策记录 + 一页"量产技术基线"。
