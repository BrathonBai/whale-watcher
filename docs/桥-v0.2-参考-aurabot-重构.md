## 1. 为什么看那个项目

它就是"一个 DSH 插件怎么把外部世界接进来"的现成答案：QQ 是它的设备，我们的 Watcher 是设备。
两边的问题同构——外面有事件进来、要交给 DSH 的大脑、要把结果发出去、要能热改配置、要能给自己
开一个面板。它把这套东西磨了十几个模块，踩过的坑基本就是我们要踩的坑。

| 我们缺什么 | aurabot 里对应的东西 |
|---|---|
| 设备对话进不了 DSH 会话，只能自己维护 8 轮上下文 | `src/chat/hub.js` 一聊天一 DSH 会话，`agent.followup` 投递，`session/event` 收回答 |
| 插件之间没法互相用 | `src/core/bridge.js` 的 `ctx.provide('aurabot', …)` + `ctx.get('aurabot')` |
| 一个工具定义写错就整片工具消失 | `src/tools/tools.js` + `src/core/modules.js` 的出错隔离、逐条登记、注销器是函数 |
| 改了设置要重启 | `src/core/config.js` 默认值 ← 用户覆盖项，保存即生效 |
| 没有面板 | `src/host.js` 的 `/aurabot/api/*` + `client/client.js` 单页面板 |
| 外部程序没法用 | `src/core/bridge.js` 的开放 HTTP（Bearer + `timingSafeEqual`）+ 事件环 `events(after)` |
| 长语音/长回复的处理 | `src/voice/tts.js`、`src/local/local.js`（本地接口模板：合成/识别/生图都能换成本机进程） |

**没有抄的**：OneBot/SnowLuma 网关、人格与心情、QQ 空间、B 站、抖音、小黑盒、翻唱、表情包。
那些是"住进 QQ"特有的，跟具身节点无关。

## 2. 抄过来的四条做法（都在新代码里）

### 2.1 设备有自己的一间 DSH 会话

```js
// lib/brain.js
const ws   = await ctx.get('workspaceRegistry').create(dir, '具身Agent · Watcher')
const r    = await ctx.get('sessionController').create({ workspaceId: ws.id, agentPreset })
await agent.followup({ id: randomUUID(), role: 'user', content: [{ type: 'text', text }],
                       source: { kind: 'embodied-device' } })
// 回答从 ctx.on('session/event') 的 assistant/message → turn/end 收口
```

好处不是"更好看"，是三个具体能力：
- 设备说的每句话都能在侧栏点开看，**可以插话**（在 GUI 里打字，设备会念出来）；
- 用的是同一套工具和记忆，不再有"设备这边的 AI 什么都不会"；
- 历史在 DSH 里，插件重启不丢。

`workspaceRegistry / sessionController / agents` 全部走 `ctx.get()`（软依赖），
拿不到就退回 llm 模式——不会因为少了哪个服务就整个插件不启动。

### 2.2 服务暴露 + 工具登记都要能撤

```js
ctx.provide('embodied', { say, face, submit, listen, events, status })   // 别的插件：ctx.get('embodied')
const off = ctx.tools.register(tool)   // 注销器是函数，不是 .off()
ctx.effect(() => ctx.on('session/event', handler), 'session/event')
```
停插件时工具、事件、服务一起下掉，不留半截。

### 2.3 配置：默认值 + 覆盖项，保存即生效

`lib/config.js`：`DEFAULTS ← config.json ← cordis.patch.yml`，三层叠。
面板 POST `/api/config` 写完盘立刻替换内存对象，`cfg.get().x` 下次用到就是新值。
**不写默认值到用户文件**，升级不会把旧配置冲掉。

### 2.4 事件环 + 开放接口

`lib/device.js` 维护带序号的上行事件环（默认 200 条），`device_events` 工具和
`GET /events?after=` 都读它。这是"大脑不在场时，设备那边发生了什么"的唯一凭据。

## 3. 顺手修掉的四个真问题（有日志证据）

日志：`%LOCALAPPDATA%\hubdev\bridge.log`（同一路径继续写，工具链不用改）。

| # | 现象（日志原文） | 根因 | 修法 |
|---|---|---|---|
| 1 | `模型第 1/2/3/4 次回空，回退重试` → `四次都没拿到回复` | 历史里的 assistant 消息被原样塞进 `llm.stream`。DSH 的 `GenerateOptions` 只接受持久 `Message`（带 `id`/`source`）或**user-role** 的 request-only 值；assistant 缺 `id/source` 会被适配器拒绝，终止分片是 `{kind:'error'}`，老代码当成"空回复"重试四次 | 默认走会话模式；llm 回退只用一条合法 user 消息（最近几轮拼成"对话记录"），并把 `finish.failure.code` 原样报出来 |
| 2 | `[asr] '"…python.exe"' 不是内部或外部命令` → `ASR 常驻进程退出：1` → 每句退回单次识别（+2.5 s） | `spawn('cmd.exe', ['/d','/s','/c', 带引号的命令])`：cmd 把首引号留在 token 里 | `spawn(cmd, { shell: true })`，由 Node 拼外层引号。实测 `READY` → `OK\t晚上好。`，之后每句 ~90 ms |
| 3 | `13:50:13 TTS 流式 101226 B` → 紧接着 `设备断开` → `13:50:14 重连`（一晚上十几轮） | 整段 PCM 一次性推给设备，音频队列灌爆后固件复位 | 分句合成 + 首包留 1.2 s 余量 + 之后每 200 ms 补 0.28 s（`lib/speech.js`） |
| 4 | 每次 `text` 上行只有一个 `lastEvent`，大脑不知道"刚才按了三次键" | 没有事件留存 | 事件环 + `device_events` 工具 + 面板实时列表 |

另外把 `asrCommand` 里那串 python 路径的引号问题一起修了（单次识别路径也走 `shell:true`）。

## 4. Watcher 上现在能怎么交互

固件 v0.8 的能力边界（`%LOCALAPPDATA%\hubdev\device\main\proto.h`）：

**下行** `welcome / say{text,mood} / face{mood} / audio+audio_end / record{seconds} / mic{auto} / ping / result`
**上行** `hello / press{edge,count} / level{v} / text / state / sound{kind,level,ms} / voice{PCM} / diag / pong`

`mood` 不只是表情——`render.cc` 的 `PetClipFor` 拿它选桌宠动画：

| mood | idle | blink | listen | think | speak | happy | sad | error |
|---|---|---|---|---|---|---|---|---|
| 动作 | 待机 | 待机 | 待机 | **张望** | **挥手** | **蹦跳** | **挠痒** | 张望 |

四条交互通道：

1. **按住说话**（主力）：按下 → `face listen` + 打断正在念的那句 → 松手录音上传 →
   `asr`（sherpa-onnx 常驻，~90 ms）→ 会话 → 回答上屏 + breeze 念出来。
2. **双击重播**：设备不存回复音频，桥这边记 `lastSpoken`，双击重放。
3. **大脑主动**：六个工具 `device_say/face/listen/status/events/mic`。
   例：这边跑完一个构建，让设备挥手说"跑完了"。
4. **面板 / HTTP / 别的插件**：`/panel` 点按钮；`POST /say`；`ctx.get('embodied')`。

## 5. 怎么验（不用等硬件）

```powershell
cd ~/.dsh/plugins/dsh-embodied-bridge
node --test test/protocol.test.mjs   # 10 项协议单测
node test/loop.mjs                   # 端到端（假 ctx + 假设备）：握手/说话/工具/HTTP/录音
node test/session.mjs                # 会话模式端到端（假 DSH 宿主，含 session/event 收口）
```

两个 e2e 都是"真插件 + 假外壳"，改一行就能再跑一遍，不依赖 DSH 和板子。

**真机联调**（设备开机后）：

```powershell
node test/fake-watcher.mjs ws://127.0.0.1:7788/device   # 虚拟 Watcher，先确认桥这侧没问题
# 再开真设备：它自己会广播 {"t":"who"} 到 255.255.255.255:7789，
# 桥用"收到包的源地址"回话，所以换了网络（本机现在 192.168.66.161）也不用重刷固件。
curl http://127.0.0.1:7788/health
```

生效方式：**重启 DSH**（新代码才能进进程）。重启后第一件事看侧栏有没有
`具身Agent · Watcher` 工作区、以及在 `%LOCALAPPDATA%\hubdev\bridge.log` 里等这两行：
`为设备新开 DSH 会话 xxxxxxxx` / `ASR 常驻进程就绪（之后每句 ~90 ms）`。

## 6. 还欠什么

- **会话模式的第一次真机验证**：本机现在设备离线（`/health` 里 `device: null`），
  会话链路只用假宿主验过。设备开机后第一次说话，留意日志里 `[session] 答：…`。
- **会话里的预设**：现在用 DSH 默认 preset（带全部工具）。若希望设备那边只能"说话不能改代码"，
  配 `preset` 指向一个收窄的 preset，或在 `brain.ensureAgent` 里加
  `agent.ctx.tools.restrict({ deny: [...] })`（aurabot 是这么做的）。
- **设备端还是硬编码 URL 优先**（`wifi_local.h` 的 `ws://172.16.1.222:7788/device`），
  发现失败才广播。要么把 `CONFIG_HUB_BRIDGE_URL` 清空只靠发现，要么每次换网重刷——
  建议下一版固件把"发现优先"打开。
- **鉴权**：`/device` 是局域网明文，谁都能连。要出公网先加 token + TLS。
