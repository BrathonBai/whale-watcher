# 新轮子：Hub —— 可扩展具身节点运行时

> 目标：不复刻小智。做一个**能力可以在运行时生长**的设备运行时，让 ESP32 级别的硬件变成"能被远端智能体驱动的标准外设"。
> 实验材料：SenseCAP Watcher（视觉节点）+ M5Stack Cardputer-Adv（手持输入节点）。

---

## 0. 先说清楚"超过小智"指什么

不是功能更多，是**架构上高一个维度**。五条硬指标：

| # | 指标 | 小智现状（读过源码） | Hub 怎么做 |
|---|---|---|---|
| 1 | **加硬件不用重编固件** | 必须写 C + 重编 + 刷机，且无 A/B 兜底 | 能力用**描述符（JSON）**声明，运行期注册；本地/侧边车/服务端三种来源 |
| 2 | **工具是数据，不是代码** | `AddTool()` 编译期写死 12 个 | 描述符 → 自动生成 MCP 工具 + 事件源 + UI 控件 |
| 3 | **断网有行为** | 断网基本是哑终端（只有唤醒词和本地 UI） | 内置**反射弧规则引擎**，事件→动作全本地可跑 |
| 4 | **视觉是常驻的** | 摄像头只在 `take_photo` 时被调一次 | Himax 端侧检测持续跑 → 事件流；只在"值得想"时才升级到云端 VLM |
| 5 | **多设备是一个身体** | 单机设计，无跨设备语义 | ESP-NOW 事件网格：两台设备是同一个 agent 的两处身体 |

## 1. 两台实验机的真实定位

| | **SenseCAP Watcher** | **M5Stack Cardputer-Adv** |
|---|---|---|
| SoC | ESP32-S3 @240MHz，**8MB PSRAM**，32MB flash | ESP32-S3**FN8**，512KB SRAM，**无 PSRAM**，8MB flash |
| 显示 | 412×412 圆屏（SPD2010，SPI3） | 240×135 IPS（ST7789V2） |
| 输入 | 旋钮（41/42）+ 触摸 | **56 键键盘** + IMU **BMI270** |
| 音频 | 单麦 + 1W 喇叭（ES7243E/ES8311，24k） | 65dB MEMS 麦 + ES8311 + NS4150B + 3.5mm |
| 视觉 | **OV5647 + Himax HX6538（NPU）**，走 SPI2 | 无 |
| 其他 | Grove I2C、2×GPIO、400mAh | IR 发射、SD、Grove I2C、**1750mAh** |
| 角色 | **眼睛 + 表情**（固定安装的观察者） | **手 + 脸**（手持输入 / 遥控 / 文字终端） |

结论：两者互补，正好凑成"一个 agent 的两处身体"。Watcher 看世界，Cardputer 收指令。

## 2. 分层架构

```
┌──────────────────────── 应用层（可换）────────────────────────┐
│  反射弧规则（本地）        会话/人格（远端）        调试面板      │
├──────────────────────── 能力层（运行期生长）──────────────────┤
│  Capability Registry                                          │
│   ├─ 内置能力：audio_in / audio_out / display / camera / imu   │
│   ├─ SD 卡描述符：cap_*.json                                  │
│   ├─ 侧边车（UART/I2C）：外部 MCU 上报的 ext.*                  │
│   └─ 服务端下发：tools/register                                │
├──────────────────────── 内核层（稳定）────────────────────────┤
│  Event Bus  │  Rule Engine  │  Scheduler  │  Store(LittleFS)   │
├──────────────────────── 传输层 ───────────────────────────────┤
│  WebSocket(JSON-RPC 2.0 + Opus 二进制) │ ESP-NOW 网格 │ UART 桥  │
├──────────────────────── 平台层（复用 ESP-IDF 生态）───────────┤
│  esp-sr(WakeNet9) │ esp_codec_dev │ LVGL9 + esp_lcd │ sscma_client │
└───────────────────────────────────────────────────────────────┘
```

**关键约束**：内核层不含任何具体硬件。内核只认识"能力"和"事件"。加一个传感器 = 加一个能力描述符，内核一行不改。

## 3. 核心抽象

### 3.1 能力描述符（Capability Descriptor）

一份 JSON 同时描述**怎么读**、**对谁可见**、**怎么显示**：

```json
{
  "id": "ext.imu",
  "kind": "sensor",
  "title": "六轴姿态",
  "link": { "bus": "i2c", "addr": "0x68", "driver": "bmi270" },
  "sample": { "interval_ms": 50, "fields": ["ax","ay","az","gx","gy","gz"] },
  "events": [
    { "name": "moved", "when": "mag(accel) > 0.4", "cooldown_ms": 3000 },
    { "name": "still",  "when": "mag(accel) < 0.05 for 5000ms" }
  ],
  "tools": [
    { "name": "get_motion",
      "description": "读取当前姿态与是否被移动",
      "schema": { "type": "object", "properties": {}, "required": [] },
      "returns": "json" }
  ],
  "ui": { "widget": "imu_gauge", "priority": 20 }
}
```

Hub 看到这份 JSON 会自动：
1. 初始化 I2C 驱动（`bus/addr/driver`）
2. 按 `sample.interval_ms` 起采样任务
3. 把 `events[].when` 编译成规则，命中就向 Event Bus 发 `ext.imu.moved`
4. 生成 MCP 工具 `ext.imu.get_motion`（远端 LLM 立刻可见）
5. 在屏上挂一个 `imu_gauge` 控件（可选）

→ **加硬件 = 往 SD 卡放一个 JSON。** 这是小智做不到的那一步。

### 3.2 事件总线

```cpp
// hub/event_bus.h（头文件即契约，实现 ~200 行）
enum class Src { Local, Remote, Timer, Net };

struct Event {
    std::string topic;        // "ext.imu.moved" / "audio.wake" / "camera.person"
    Src src;
    int64_t ts_ms;
    std::string json;         // 载荷
};

class EventBus {
public:
    using Handler = std::function<void(const Event&)>;
    int Subscribe(const std::string& topic_prefix, Handler h);   // 支持通配 "ext.imu.*"
    void Unsubscribe(int id);
    void Publish(const Event& e);                                // 在 hub 主任务派发
    void PublishAsync(Event e);                                  // 线程安全投递
};
```

规则：**所有输入都是事件**（语音、视觉、IMU、键盘、定时、网络、其他设备）；**所有输出都是 sink**（TTS、屏、RGB、继电器、上报、转发给另一台设备）。反射弧和慢思考只是同一条总线上的两条路径。

### 3.3 反射弧 DSL（本地规则，断网可用）

```json
{
  "id": "r_person_wake",
  "when": "camera.person.count > 0",
  "for_ms": 0,
  "cooldown_ms": 5000,
  "then": [
    { "op": "display.wake" },
    { "op": "display.text", "args": { "text": "看到人了" } },
    { "op": "net.notify",   "args": { "topic": "vision.person" } }
  ]
}
```

编译期不存在，运行期从 LittleFS 读。改一行 JSON，重启即生效——不用刷机。

### 3.4 传输：JSON-RPC 2.0 + 二进制音频

控制面走 JSON-RPC（跟 MCP 同构，将来直接兼容 MCP）：

```
initialize / tools/list / tools/call         ← 远端调设备
events/subscribe / events/push               ← 设备推事件
audio/up (Opus 16k) / audio/down (Opus 24k)  ← 二进制帧，首字节 0x01/0x02
```

设备侧**同时是 MCP server 和 MCP client**：
- server：把自己的能力暴露给远端 LLM
- client：可以调用侧边车/另一台设备的工具（ESP-NOW 或 UART）

## 4. 里程碑（每步都有可验收的产物）

| 阶段 | 内容 | 验收标准 | 预估 |
|---|---|---|---|
| **M0** | Cardputer 上跑通 Hub 内核：EventBus + 2 个内置能力（IMU、键盘）+ 控制台打印 | 摇一下板子，串口打印 `ext.imu.moved`；按键打印 `key.press` | 1 天 |
| **M1** | Watcher 上跑同源内核：屏 + 麦 + 唤醒词；两台 ESP-NOW 互通 | 按 Cardputer 的键，Watcher 屏幕上出现这行字 | 2 天 |
| **M2** | WebSocket 传输 + 最小 Python 服务端 | 服务端 `tools/list` 能看到两台设备的能力；`tools/call` 能点亮 Watcher 的屏 | 3 天 |
| **M3** | 描述符驱动：SD 卡 JSON → 自动生成工具/事件 | 插一张写着 `cap_led.json` 的 SD 卡，LLM 立刻多一个 `ext.led.set` 工具 | 2 天 |
| **M4** | 反射弧 DSL + Himax 常驻检测 | 拔掉路由器，人走过 Watcher 仍会亮屏并显示文字 | 3 天 |
| **M5** | 语音闭环（VAD→Opus→ASR→LLM→TTS） | 说"帮我看下桌上有什么"，Watcher 拍照后念出答案 | 5 天 |

M0 只用 Cardputer（便宜、有 IMU 和键盘、无摄像头复杂度），不碰 Watcher，零风险。

## 5. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | ESP-IDF（5.4 起，视板级支持可到 6.x） | 唯一能同时驱动这两块板的生态 |
| 唤醒词 | esp-sr WakeNet9（"你好小智"可换） | 现成、跑得动 |
| 音频 | esp_codec_dev + ES8311/ES7243E | 两块板都用得上的驱动 |
| 显示 | LVGL 9 + esp_lcd（两块板驱动不同，内核只认 `Display` 接口） | 统一抽象 |
| 摄像头 | sscma_client（Watcher 的 Himax）+ 端侧检测事件 | 别人没做的点：视觉常驻 |
| 组网 | ESP-NOW（同信道零配置）+ Wi-Fi（云端） | 双设备低延迟互联 |
| 认知 | 服务端任意 LLM（OpenAI 兼容 / 本地） | 设备端不背模型 |
| 构建 | `idf.py` + 每板一个 `boards/<name>` 目录，内核零条件编译 | 换板不动内核 |

**复用 vs 自研**：驱动/编解码/UI **全部复用**，只自研 ①事件总线+能力注册 ②反射引擎 ③传输协议 ④双设备网格。这四样是小智没有的，也是"新轮子"的全部价值。

## 6. 明确不做（把范围钉死）

- 不做通用 OS（不搞动态 ELF 加载）
- 不在设备端跑 LLM
- 不追求 100% 离线的语义理解（离线只保证**反射弧**，理解靠云）
- 不兼容小智的 WebSocket 协议（协议自定，省得被它绑住）——但如果哪天想复用它的服务端，加个适配层即可
- 不做 OTA 灰度/双槽策略（M3 之前用 USB；上线前再补，Watcher 的 `ota_1` 是空的，必须自己开双槽）

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| Cardputer **无 PSRAM** | 音频缓冲、LVGL 大图吃紧；摄像头类应用基本无缘 | 它只做"输入+小屏"，视觉全交给 Watcher |
| 语音闭环细节多（AEC、打断、回声） | M5 容易拖长 | 先用"按键说话 + 半双工"，把 AEC 放到 M6 |
| Watcher 无 A/B 槽 | 刷坏就砖 | 32MB 全片 dump 在手（`backup/full_flash_32MB.bin`）；立项第一件事是改分区表开双槽 |
| 工具链 | 本机 IDF 解压损坏 | 先修；或换一台干净机器 |
| 自研协议无生态 | 没有现成服务端 | M2 就写一个 200 行的 Python hub 服务端，自己吃自己的狗粮 |

---

## 8. 一句话

**小智是"一个能语音对话的设备"；Hub 是"一台可以被远端智能体随时长出新的感官和手脚的机器"。**
前者靠编译期堆功能，后者靠运行期长能力——这就是"超过"的地方。
