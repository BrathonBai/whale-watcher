> 结论先说：**触摸硬件确认存在并已初始化**（`SPD2010: Touch panel create success`），
> 但首次读数据出现 I2C NACK，**还没拿到一次真实触摸坐标**——需要上手摸一下看日志再定坐标/链路。
>

## 1. 硬件事实（官方 + BSP）

- 屏幕：**1.45" 412×412 圆形电容触摸屏**（[Seeed 规格](https://wiki.seeedstudio.com/watcher_hardware_overview/)："Touchscreen with 1.45-inch, 412×412 resolution"）。
- 触摸控制器：**SPD2010**，独立 I2C1：`SDA=GPIO39`、`SCL=GPIO38`、`400 kHz`、地址 `0x53`；
  `INT` 接在 PCA9535 `P0.5`（本实现用轮询，不接中断）；`RST` 与 LCD 共用（配置为 NC，避免复位已初始化的屏）。
- 我们的 v2 之前只初始化显示面板，触摸从未启用；`input.cc` 只接管旋钮 + 按键。

## 2. 实现（`touch_input.cc/.h`，已刷入）

- I2C 用 **new i2c_master 驱动**（IDF 5.5 的 `esp_lcd_new_panel_io_i2c` 按 bus 类型选 v2 实现；BSP 的 legacy 写法不适合直接搬）。
- SPD2010 触摸 panel IO 手动填（组件宏的 designated-initializer 顺序与 IDF 5.5 结构体不一致，会编译报错）。
- 50 Hz 轮询任务（栈 3 KB，prio 3）；手势识别在触摸任务里完成，**只置事件标志**，
  由 UI 任务（`TickTask`）统一执行动作，避免跨任务改 UI 状态。
- 手势与动作：

| 手势 | 判定 | 动作 |
|---|---|---|
| 单击 | ≤350ms、位移 ≤30px | **摸摸头**：随机互动动画 + 台词（与旋钮同一套） |
| 双击 | 两次单击间隔 ≤320ms、位置相近 | **再来一次**（跳过 2.2s 冷却） |
| 长按 | ≥700ms、位移 ≤30px | **菜单**（复用按键长按语义） |
| 上/下滑 | 位移 ≥60px 且竖直为主、≤600ms | **音量 ±5%**（下滑减、上滑加） |

- 触摸事件通道：`volatile int s_touch_evt / s_touch_dy` → TickTask 里 `HandleTouch()`。

## 4. 触区分派（第二版，已刷入）

- **点顶部（y<96）**：显示状态字幕（在线 dBm / 电量 / 音量）。
- **点角色区（96≤y≤290）**：摸摸头（随机互动动画 + 台词）。
- **点字幕区（y>290）**：有下一页 → 手动翻页；只有一页 → 当摸摸头。
- **双击**：再来一次（跳过冷却）。
- **长按 ≥700ms**：菜单。
- **上下滑**：音量 ±5%。
- **左右滑**：按顺序换动作（happy → wave → tickle → shy，方向可反）。

日志改成 ASCII 便于串口核对：`tp: down (x,y)`、`tp: tap x=.. y=..`、`tp: swipe dx=.. dy=..`、
`ui2: cycle clip=.. dir=..`、`ui2: vol=.. dy=..`、`ui2: tap top y=..`。

### 4.1 触摸的本地音效（Breeze 音色）

触摸不再"只动不响"：摸摸头/换动作会播一句 **内嵌 PCM 短音效**（不走网络 TTS，延迟 0）。

- 音色：**Breeze Blue**，沿用桥配置 `breezeVoiceId=voc_8yud7hz7c9q2` / `breeze-tts-2`（key 不写进仓库）。
- 5 句（**2026-11-05 公共场合安全版**）：`嘿嘿 / 在呢 / 嗯？ / 好耶 / 谢谢`；
  原版（`好舒服 / 再摸摸 / 唔，痒 / 最喜欢啦`）出门会被侧目，已废弃。
- 音量：PCM 峰值压到 **0.30**（原 0.8，约轻 8.5 dB），比对话/TTS 明显轻一档；
  另做 **1.12× 提速**（更短促、音高略升），总时长从 5.5s 降到 ~3.8s、flash 180 KB。
- 生成链路（换音色/换词只改这两步）：
  1. `node tools/gen_pet_voice_breeze.mjs` —— 用桥配置里的 Breeze 音色合成原始 PCM（24k/mono/s16le）；
  2. `python tools/make_pet_voice.py` —— 裁静音/提速/压峰值/淡入淡出，写 `firmware-v2/main/voice_pet_*.pcm`。
- 播放：`pet_voice.cc` 一次性任务调 `audio::Play()`（实时阻塞写不挡 UI/动画），`Busy` 时忽略叠加；
  只在待机互动时触发（TTS/录音中不播）。
- `.pcm` 与 `.bin` 一样被 gitignore，靠上面两步再生成。
- 后续可选：菜单加"触摸静音/出门模式"（只动不响），避免任何公共场合声音。

## 5. 下一步（按优先级）

1. **上手摸屏确认**：串口应出现 `tp: down (x,y)`；如果刷屏 NACK/无事件，按下面顺序排查：
   - I2C1 地址扫描（0x08–0x77）确认 0x53 是否 ACK；
   - 给 SPD2010 一个显式复位脉冲（与 LCD 共用脚，需在显示初始化后小心操作）；
   - 首读前延时加长 / 读失败重试（驱动 `read_data` 失败不致命）；
   - 若地址不符（不同批次面板可能是 CHSC6X 0x2E），换 `esp_lcd_touch_chsc6x` 驱动。
2. 坐标校准：日志确认 X/Y 是否需要 mirror/swap（当前按 BSP：swap=0/mirror=0）。
3. 手势分区（下一版）：
   - 点**角色区**（y 96–276）→ 随机回应；点**字幕区**（y 304–382）→ 翻页/重播；点**顶部**→ 状态（在线/音量/电量）；
   - 左右滑 → 切换动作/情绪；
   - 按住左右搓 → 连续摸摸头（复用旋钮的 cooldown）；
   - "Q 弹"：先用 happy 跃动 clip 表达；真挤压需 render 支持（成本中等，触摸通了再评估）。
4. 触摸日志节流：确认可用后把每点日志降为 debug，避免刷屏。

## 6. 事故记录：误刷 Waveshare 板（COM7）

- 时间：2026-11-04 00:4x。现象：Watcher 的 CH342（COM5/COM6）消失，系统出现 COM7（VID_303A Espressif native）。
- 误操作：把 `hub_v2.bin`（6,518,848 B）写到 COM7 的 `0x200000`。
- 事后只读回分区表：`app0 0x10000–0x210000`、`app1 0x210000–0x410000`、`ffat 0x410000–0xFF0000`。
  写入覆盖：app0 尾部 64 KB、**整个 app1**、**ffat 前 ~4.2 MB**。
- 该板仍能启动（app0 开头完好），但 OTA 备份与文件系统头部可能损坏。**恢复需要原厂固件/备份**；未再对其做任何写操作。
- 教训：刷机前必须用 **CH342 的设备名/VID** 确认端口（`USB-Enhanced-SERIAL CH342`），不能只看 COM 号。
