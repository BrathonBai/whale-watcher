# 协议 v2 契约（设备 ⇄ 桥）

> **本文件由 `tools/gen-contract-doc.mjs` 生成，请勿手改。**
> 唯一事实源是 `bridge/lib/contract.js`；改了契约就重新生成，并跑
> `node test/contract.test.mjs`（它会比对本文件与代码是否一致）。
>
> 上位背景：v0.2 的桥是照 v1 固件（fw 0.8）写的，v2 上来后只"让它连上"，
> 没有反向核对契约，于是 press/record/mic/level/sound/diag 这些消息在 v2 里
> 根本没有对端，工具却照样注册给模型 → "工具都在、用起来空转"。
> 这一版的原则：**设备没有的，桥就不假装有**。

- 协议版本（桥侧）：2
- 设备自报：fw=`hub_v2` · ver=`0.3` · 屏 412×412
- 摄像头：240×240 JPEG，≤ 4 MB，周期 8000 ms
- 音频：24000 Hz / 16 bit / 1 ch，单段 ≤ 10 s
- 音频编码：`pcm` / `opus` / `adpcm`（缺省 `pcm`）；opus = 每包 20 ms、编码 16 kHz mono、audio 头 rate 填 24000（设备解码输出率）、裸包 ≤ 1275 B
- 桌宠素材：三段（idle / look / wave），10 fps

## 一、设备 → 桥（只有 4 种）

| t | 字段 | 固件出处 |
|---|---|---|
| `hello` | fw, board, ver(字符串), cam, w, h；可选 codecs[] / opusRate | app_ui.cc:126（ver 是字符串 "0.2"，cam=1, w/h=240）；2026-11-03 起可选 codecs[] / opusRate |
| `pong` | 可选 bufMs / underruns / reconnects / rssi / codec（老固件没有） | app_ui.cc:255（收到 ping 回 pong）；2026-11-03 起可选带 bufMs/underruns/reconnects/rssi/codec |
| `image` | bytes, w, h, seq + 二进制分块 | app_ui.cc:294-309（文本头 + 16KB 二进制分块） |
| `voice` | bytes, rate, seq + 二进制分块 | app_ui.cc:141 + proto.cc:401（BuildVoice 头 + 分块） |

其它任何 `t` 一律回 `UNSUPPORTED_UPLINK`（**不是**"向前兼容地解析成功"）。

## 三、v2 不具备的能力（写清原因，工具因此不注册）

| 消息 | 为什么没有 |
|---|---|
| `press` | 按键只在设备本地起作用（录音开关/菜单），v2 不上行 press |
| `record` | v2 不处理 record 下行：录音只能由设备物理按键触发 |
| `mic` | v2 不处理 mic 下行：没有免按键自动录音 |
| `state` | v2 不上报电量/表情状态 |
| `level` | v2 不上报旋钮/触摸数值 |
| `sound` | v2 不做环境声分类 |
| `diag` | v2 不上报自检遥测 |
| `text` | v2 没有文本上行通道（按键录音后走 voice） |

## 四、音频编码协商与自适应（2026-11-03）

设备能力：hello 可选带 `codecs`（如 `["pcm","opus"]`）与 `opusRate`；
老固件没有这两个字段时，桥按"只有 PCM"处理——**缺字段不是错误**。

| 项 | 约定 |
|---|---|
| audio 头 `codec` | `pcm` / `opus` / `adpcm`；缺省 `pcm` |
| ADPCM（2026-11-13，BLE 链路） | 上行 hello.uplink=`adpcm`、voice 头 `codec:"adpcm"`；块 = 1024 B（4 B 头 + nibbles）= 2041 采样 = 85 ms，12041 B/s；voice/audio 头可带 `samples`（解码后采样数） |
| ADPCM 参考实现 | `lib/adpcm.js` 与 ffmpeg `adpcm_ima_wav` 同构：解码结果逐采样 0 差异（`test/adpcm.test.mjs` + `test/fixtures/adpcm-vectors.json`）；固件 `adpcm.cc` 必须与共享向量逐字节一致 |
| opus 每帧 | 一个 WS 二进制帧 = 一个裸 Opus 包（20 ms、16 kHz mono、无长度前缀、≤ 1275 B） |
| opus audio 头 | `rate=24000`（设备解码输出率）、`bits=16`、`ch=1`、`bytes=0`、`seq` 递增 |
| opus 编码 | ffmpeg libopus（`voip`），输入 PCM 24k mono → 编码率 16 kHz |
| audio_end | 语义不变 |
| pong 诊断 | 可选 `bufMs` / `underruns` / `reconnects` / `rssi` / `codec` / `mtu` / `txDrop` / `rxDrop``transport`（缺字段不能报错） |

自适应档位（只在 opus 生效；**每段回复只选一次**，句子中间不切换）：

| 档位 | 判据（最近 6 条 pong） | 码率 |
|---|---|---|
| 健康 | 平均 bufMs ≥ 120 ms 且新增欠载 ≤ 0 | 24000 bps |
| 中等 | 平均 bufMs ≥ 60 ms 且新增欠载 ≤ 2 | 16000 bps |
| 差 | 其它（缓冲偏低 / 欠载多 / 没 pong） | 8000 bps |

回退策略（显式，不静默换编码）：

- 连续 2 段判"差" → 回退 PCM 24000 Hz；健康度恢复后自动回 opus；
- 连接后 60 s 没有 pong → 回退 PCM；
- 编码不可用/失败（ffmpeg 缺失、连续失败 2 次）→ 本段回退 PCM，
  原因写入 `/api/state.audio.lastEncodeError`（`/api/diag` 可解释）。

## 六、HTTP 路由

- 只读：`/health` `/api/state` `/api/diag` `/events` `/commands` `/moods` `/panel` `/` `/shot.jpg`
- 动作（本机免令牌 / 配了 panelToken 要 Bearer）：`/say` `/api/speak` `/api/face` `/shot` `/api/config` `/api/linktest`
- 历史接口（返回 501 + 原因，不是 404）：
  - `/listen`：v2 没有 record 下行，无法远程触发录音；请按设备上的按键
  - `/mic`：v2 没有 mic 下行，无法远程开关自动录音
