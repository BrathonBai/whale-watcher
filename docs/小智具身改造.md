# 小智版 Watcher 具身改造（修正版）

> ⚠️ **重要修正**：`具身节点架构.md` 与 `魔改方案.md` 是基于 Seeed 官方工厂固件源码（taskflow / image analyzer / http alarm）写的。
> 你这台是**国内版，跑的是小智（xiaozhi-esp32）v1.8.5**，两套固件的数据通路完全不同。
> 那两份文档只在"哪天刷回 Seeed 固件"时才成立。本文才是你机器的真实地图。

## 1. 身份已实测确认（不是猜测）

**flash 分区表**（从设备 0x8000 读出，与小智 `partitions/v2/32m.csv` 一致，和 Seeed 工厂布局完全不同）：

```
nvsfactory  0x9000    0x32000
nvs         0x3b000   0xd2000
otadata     0x10d000  0x2000
phy_init    0x10f000  0x1000
model       0x110000  0xf0000      <- Himax 模型
ota_0       0x200000  0xc00000     <- 当前固件
ota_1       0xe00000  0xc00000
```

**app 描述符**（0x200030）：`version=1.8.5`、`project=xiaozhi`、`built=2025-08-08 17:51:16`、`idf=v5.4.1`。

**两个 app 槽的实况（32MB 全片读出后确认）**：

| 槽 | 内容 |
|---|---|
| `ota_0` @0x200000 | 小智 **1.8.5**，IDF v5.4.1 编译 |
| `ota_1` @0xe00000 | **空白**（0xCC 填充，未写入任何固件） |

→ 也就是说**没有 B 槽兜底**：OTA 写坏就没得回退。32MB 全片 dump 是唯一救生圈，必须保住。

**`model` 分区不是 Himax 视觉模型**，是 esp-sr 的唤醒词模型：

```
0x110010  "wn9_nihaoxiaozhi_tts"   -> WakeNet9, 唤醒词“你好小智”
```
Himax 的视觉模型在它自己那颗独立 16MB flash 里（另一个芯片，ESP32 侧看不到）。

**编译期端点**（字符串就躺在 flash 里）：

```
OTA : https://api.tenclass.net/xiaozhi/ota/
WS  : wss://api.tenclass.net/xiaozhi/v1/
AP  : http://192.168.4.1          （配网热点 Xiaozhi-ACB1）
```

**NVS 里现有的键**（我从 flash 里直接读出来的）：

```
board      / wifi: ap.ssid, sta.ssid, bssid.set ...
mqtt:      client_id
websocket: url = wss://api.tenclass.net/xiaozhi/v1/ , token = test-token
```

**设备端 MCP 工具已内置**：字符串表里有 `tools/list`、`tools/call`、`take_photo`、`set_volume`。也就是说小智已经把「拍照」「调音量」等能力做成了可被 LLM 调用的工具。

## 2. 这具身体的实际规格（`boards/sensecap-watcher/config.h` 实证）

| 部位 | 实现 |
|---|---|
| 语音输入 | ES7243E ADC → I2S（MCLK 10 / WS 12 / BCLK 11 / DIN 15），**24 kHz** |
| 语音输出 | ES8311 DAC → I2S（DOUT 16）+ 功放由 IO 扩展器 P1.4 控制，**24 kHz** |
| 屏幕 | SPI3，CS 45，DC 1，背光 8，412×412，RGB565@40MHz |
| 触摸 | 独立 I2C1（SDA 39 / SCL 38），INT 在扩展器 P0.5 |
| 旋钮 | 编码器 A=41 / B=42，按键在扩展器 P0.3 |
| 摄像头/AI | Himax 走 **SPI2**（CS 21、SYNC 扩展器 P0.6、RST P0.7、12MHz），烧写走 **UART1（TX17/RX18 @921600）** |
| 电源域 | 全在 PCA95xx 扩展器：SD/LCD/SYSTEM/AI_CHIP/CODEC_PA/GROVE/BAT_ADC（`BSP_PWR_START_UP`） |
| 电池 | ADC GPIO3，分压 (62+20)/20 |
| Grove | 扩展器 P1.6 供电，通用 I2C 在 GPIO47/48 |

→ 对比 Seeed 固件那套（UART2 19/20 对外报警），**小智版本没有"对外 UART 报警"这条线**；它的对外通道是 **WebSocket/MQTT 音频流 + MCP 工具**。

## 3. 三条接入路径

### 路径 A：不刷机，改 NVS 把设备导到你自己的服务器（今天就能做）

设备找 OTA 地址的逻辑（`main/ota.cc:56`）：

```cpp
Settings settings("wifi", false);          // 只读打开 NVS 命名空间 wifi
std::string url = settings.GetString("ota_url");
if (url.empty()) url = CONFIG_OTA_URL;     // 出厂 = api.tenclass.net
```

**`ota_url` 这个键，全仓库只有这一处引用** —— 没有任何配网界面能设置它。所以要改，只能写 NVS。

已备好两个工件：

| 文件 | 作用 |
|---|---|
| `embodied/ota_stub.py` | 假的 OTA 服务，返回 `{"websocket":{"url","token"},"activation":{...},"server_time":{...}}`，把设备导到你的 WS 服务端；顺便打印设备的 MAC / UUID / UA |
| `scripts/make_nvs_ota_url.py` | 生成含 `wifi/ota_url` 的 nvs 分区镜像（已跑通，生成 0xd2000 字节镜像） |

操作（**代价：会清空 NVS → WiFi 凭据丢失，设备回到配网模式，身份重新激活**）：

```powershell
# 1. 起 OTA 桩（把 WS_URL 改成你的服务端）
cd D:\DSH_workspace\watcher-mod\embodied
$env:WS_URL="ws://192.168.0.17:8000/xiaozhi/v1/"; $env:OTA_TOKEN="mydevice"
python ota_stub.py

# 2. 生成 nvs 镜像
cd D:\DSH_workspace\watcher-mod
python scripts\make_nvs_ota_url.py --url http://192.168.0.17:8003/xiaozhi/ota/ --size 0xd2000 --out backup\nvs_new.bin

# 3. 刷 NVS（只动 0x3b000 这 860KB，不碰固件）
esptool --chip esp32s3 -p COM6 -b 460800 write-flash 0x3b000 backup\nvs_new.bin

# 4. 回滚（原分区已备份）
esptool --chip esp32s3 -p COM6 -b 460800 write-flash 0x3b000 backup\nvs_orig.bin
```

用 `http://` 而不是 `https://` 是为了免证书；小智的 HTTP 客户端接受明文地址。

### 路径 B：自己编译固件（彻底，门槛比想象中低）

**关键修正**：`AGENTS.md` 里"最低 IDF 6.0.1、推荐 release/v6.1"是针对**当前 main 分支**。
你这台跑的是 **v1.8.5，当年就是用 IDF v5.4.1 编的**（app 描述符里写着）。所以：

- 想复刻/微调 1.8.5 → 用 **IDF 5.4.x**（本机 5.5 也大致可用），不用上 6.x
- 想跟最新 main → 才需要 IDF 6.0.1+ / release-v6.1

```bash
git clone -b v1.8.5 https://github.com/78/xiaozhi-esp32 && cd xiaozhi-esp32
python scripts/build.py sensecap-watcher        # 或 idf.py -DBOARD_NAME=sensecap-watcher build flash
```
板级配置（`boards/sensecap-watcher/README.md`）：

```
CONFIG_BOARD_TYPE_SEEED_STUDIO_SENSECAP_WATCHER=y
CONFIG_ESPTOOLPY_FLASHSIZE_32MB=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions/v2/32m.csv"
CONFIG_BOOTLOADER_CACHE_32BIT_ADDR_QUAD_FLASH=y
CONFIG_ESPTOOLPY_FLASH_MODE_AUTO_DETECT=n
CONFIG_IDF_EXPERIMENTAL_FEATURES=y
```
然后改 `CONFIG_OTA_URL`（menuconfig → xiaozhi → OTA URL）指向自己。

⚠️ 本机现状：IDF 5.5 已装但**工具链解压损坏**（`libexec/include/share` 变成 0 字节文件，gcc 找不到 `cc1`），`eim fix` 重装两次都复现。要么修这台机器，要么换机器/容器装 IDF 6.1。

### 路径 C：官方控制台「固件编译」

你截图里那个控制台有 **固件编译** 标签页。如果它能让你选板子并填入自定义服务地址，那是最省事的官方路径——值得先点进去看一眼能不能配 `OTA_URL`。

## 4. "让我接管"的架构

```
┌─────────────── Watcher（身体，现成固件就行）───────────────┐
│ 唤醒词(esp-sr) → 麦克风 24k → Opus ─┐                      │
│ 喇叭 ← Opus ← TTS                  │                      │
│ 412×412 LVGL 表情 / 旋钮 / 触摸      │  WebSocket(或MQTT+UDP)│
│ Himax 摄像头 → MCP: take_photo      │                      │
│ 音量等 → MCP: set_volume            │                      │
└─────────────────────────────────────┼──────────────────────┘
                                      ▼
                        ┌──────────────────────────────┐
                        │ xiaozhi-esp32-server（脊髓）  │
                        │ VAD → ASR → LLM → TTS → 音频  │
                        │ 插件/MCP 客户端               │
                        └──────────────┬───────────────┘
                                       ▼
                        ┌──────────────────────────────┐
                        │ 大脑：你的 LLM / Agent        │
                        │ （DeepSeek / 本地 / 我）      │
                        └──────────────────────────────┘
```

- **脊髓**用现成的 `xiaozhi-esp32-server`（`main/xiaozhi-server/config.yaml`，监听 `0.0.0.0:8000`，WS 路径 `/xiaozhi/v1/`）。默认模块：SileroVAD + FunASR + EdgeTTS，LLM 可选 `DeepSeekLLM` 等。
- **大脑**：把 server 的 LLM 换成你要用的模型（OpenAI 兼容即可）；设备暴露的 MCP 工具（拍照/音量）会自动进入 LLM 的工具列表，`take_photo` 就是你"睁眼"的动作。
- **反射弧**留在设备端：唤醒词、按键、表情反馈、断网提示 —— 这些本来就在 ESP32 上跑，不需要额外做。

## 6. 风险清单

1. **改 NVS = 清 WiFi**：设备会重启进 `Xiaozhi-ACB1` 热点，用手机连 192.168.4.1 重新配网；控制台里可能变成"新设备"要重新绑定。
2. **脱钩官方 OTA**：指向自己的 OTA 后，官方云推的升级不会再来（也没有回退按钮）。想回官方：刷回 `nvs_orig.bin` 或清 NVS 重配网。
3. **1.8.5 的协议版本**：`websocket.md` 里有 v1/v2/v3 三种二进制协议，自建服务端要按设备声明的版本应答（`hello` 帧里带 `version`）。
4. **Himax 模型**：`model` 分区（0x110000，0xF0000）是小智下发的 AI 模型；换模型走官方 OTA 或 `sscma` 工具链，别乱写。
