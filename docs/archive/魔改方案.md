# SenseCAP Watcher 魔改方案（基于实机 + 官方源码仓库）

> 生成时间：2026-10-26 · 目标设备：SenseCAP Watcher（SKU=sensecap-watcher，板载 ESP32-S3 + Himax HX6538）
> 本文所有结论都来自三处实证：① Wiki/官方文档 ② 官方固件源码仓库（已 clone） ③ 直接对插着的设备做串口/烧录探测（已实测）

---

## 0. 先给结论：这机器是「全开源 + 双芯双 flash」，魔改空间非常大

| 你想要的 | 难度 | 走哪一层 |
|---|---|---|
| 不改固件，让 Watcher 把识别结果吐给自己的板子/服务器 | ★ | L1（UART / HTTP） |
| 让 AI 分析走本地模型，不碰 Seeed 云 | ★★ | L2（本地 AI 服务） |
| 换 UI、加自定义模块、加 MQTT/GPIO 报警 | ★★★ | L3（编译源码） |
| 换视觉模型 / 完全自研 AI 固件 | ★★★★ | L4（Himax 侧） |
| 加传感器、继电器、第二块 MCU | ★★ | L5（硬件接口） |

## 1. 实机盘点（已实测，不是查资料）

### 1.1 硬件事实

| 项 | 值 |
|---|---|
| 主控 | ESP32-S3 @240MHz，8MB PSRAM，**32MB flash**（实测可读满 0x0–0x2000000） |
| AI 协处理器 | Himax HX6538（Cortex-M55 + Ethos-U55），独立 **16MB flash** |
| 摄像头 | OV5647，120° FOV，固定焦距 3m |
| 屏幕 | 1.45" 412×412 触摸屏，面板驱动 **spd2010**（启动日志实测），触摸 **CHSC6X** |
| IO 扩展 | PCA95xx 16bit（日志：`IO expander initialized: ffd9`） |
| 旋钮 | 编码器 A=**GPIO41**，B=**GPIO42**（日志实测） |
| 对外 UART | **UART2，TX=GPIO19，RX=GPIO20**（uart alarm 模块占用） |
| 扩展口 | 1×Grove I2C + 1×2×4 排针（1×I2C、2×GPIO、GND、3.3V_OUT、5V_IN） |
| USB | 底部 USB-C：供电+编程；背面 USB-C：**仅供电** |
| 电池 | 3.7V 400mAh（仅备电，拔 5V 就掉） |
| 存储 | microSD ≤32GB FAT32 |

### 1.2 两个串口（CH342 双 UART，实测）

| 端口 | Windows 枚举 | 用途 |
|---|---|---|
| USB-Enhanced-SERIAL-**A** | COM5 | **Himax HX6538 侧**（Xmodem 烧写 / 模型下发），115200 直连是乱码，正常 |
| USB-Enhanced-SERIAL-**B** | COM6 | **ESP32-S3 控制台 + 烧录口**（115200，出现 `SenseCAP>` 提示符；esptool 可直接读写） |

启动日志关键行（说明串口通了、板子在线）：

```
I (365) Board: UUID=8d28a727-... SKU=sensecap-watcher
I (445) sensecap_watcher: Initialize SSCMA SPI bus
I (450) sensecap_watcher: Initialize QSPI bus      <- ESP32 与 HX6538 之间走 QSPI
I (604) sensecap_watcher: IO expander initialized: ffd9
I (1170) Knob: Iot Knob Config Succeed, encoder A:41, encoder B:42
I (1194) spd2010: LCD panel create success, version: 1.0.2
```

### 1.3 Flash 分区（源码 `examples/factory_firmware/partitions.csv`）

```
nvsfactory   data/nvs     0x9000   200K   <- 设备 EUI / 云端凭据，擦掉就回不去，务必先备份
nvs          data/nvs             840K
otadata      data/ota            0x2000
phy_init     data/phy            0x1000
ota_0        app/ota_0            12M    <- 双 OTA 槽，够塞大固件
ota_1        app/ota_1            12M
model        data/spiffs         1024K   <- AI 模型
storage      data/spiffs         6080K   <- UI 资源 / 配置
```

### 1.4 量产固件的 CLI 被裁过（重要发现）

串口 `help` 实测只有 6 条命令：

```
reboot / shutdown / battery / factory_reset / read_mac / help
```

但源码 `main/app/app_cmd.c` 里注册的是 **12 条**：`wifi_sta / ota / taskflow / factory_info / battery / bsp / record / vi_ctrl / iperf / rgb / reboot / factory_reset`。

含义：**Wiki 上那些好用的调试命令（taskflow 导入导出、bsp i2cdetect、rgb、record、force ota）你手上的量产机是没有的**。想用，必须自己编译一版 dev 固件刷进去。这就是魔改的第一道门。

## 3. 魔改路线：五层，按「投入产出比」排序

### L1 · 不烧固件，只改输出（今天就能做）

Watcher 内置一个类 Node-RED 的**任务流引擎**，模块之间用 JSON 连线。源码里现成 8 个模块：

| 模块名 | 作用 | 可调参数（源码实测） |
|---|---|---|
| `ai camera` | 摄像头 + 端侧模型推理，事件源 | `model_type` `modes` `conditions`（class/mode/type/num）`conditions_combo` `silent_period` `output_type` `shutter` |
| `alarm trigger` | 把推理结果转成报警事件 | `text` `audio` |
| `local alarm` | 本机响铃/亮灯/显示 | `sound` `rgb` `img` `text` `duration` |
| `sensecraft alarm` | 推 Seeed 云 | `silence_duration` `text` |
| `http alarm` | **POST 到你自己的服务** | `time_en` `text_en` `image_en` `sensor_en` `silence_duration` `text` `url` `token` `head` |
| `uart alarm` | **串口吐 JSON/二进制给外部 MCU** | `output_format`(0=bin/1=json) `text` `include_big_image` `include_small_image` `include_boxes` |
| `image analyzer` | **把图丢给 LLM/VLM 问问题** | `body.prompt` `body.type` `body.audio_txt`（⚠️ host 由 NVS 里的「设备 AI 服务」配置决定，任务流 JSON 里的 `url` 字段不生效，见《具身节点架构.md》§2.4） |
| `timer` | 定时触发 | — |

**最低风险玩法（不改任何代码）**：SenseCraft App 里建任务 → 详情配置 → Action 勾上 `Serial Port / UART Output`（可选带 base64 图）。Watcher 就会在 GPIO19/20 上以 115200 8N1 吐 JSON：

```json
{"prompt":"People detected","big_image":"<base64 jpg>","inference":{"boxes":[{"x":100,"y":100,"w":50,"h":60,"score":0.8,"target_cls_id":1}],"classes_name":["person"]}}
```

二进制格式是自定义包：`"SEEED"`(5B) + prompt 长度/内容 + 大图长度/内容 + 小图长度/内容 + 推理类型 + 框表 + 类名表（细节见 `tf_module_uart_alarm.h` 头部注释，写得很全）。

→ 这层能直接接 XIAO / 树莓派 / Jetson，做「人体出现 → 我的板子干活」，**完全绕开 Seeed 云**。

> 注意：要用 `taskflow -i/-e` 手写 JSON 玩更花的结构，得先有 L3 的 dev 固件（量产机没这条命令）。

### L2 · 把 AI 大脑换成你自己的（隐私 / 断网 / 省钱）

源码里写死了几个云端 host（`grep` 结果）：

```
sensecap.seeed.cc                                # 设备管理/任务下发
sensecraft-aiservice-api.seeed.cc                # VLM 分析 + 报警回调
    /v1/notification/event                       # http alarm 的默认上报路径
```

三条替换路线，从省事到彻底：

1. **用官方本地服务（最省事）**：装 `watcher_service`（Win/macOS/arm64 deb，内置 Llama 3.1 + LLaVA 或填 OpenAI Key）→ 在 SenseCraft App 的「设备 AI 服务」里填它给的 URL + Token。设备本体一行不改，图不出内网。
2. **自己实现兼容接口**：只要提供和 `/v1/...` 同形状的 HTTP 服务（收图 + prompt，回答案），设备端填你的 URL/Token 即可。
3. **改源码换 host**：`tf_module_img_analyzer.h` / `tf_module_http_alarm.h` / `app_voice_interaction.h`（`CONFIG_TALK_SERV_HOST`）/ `app_sensecraft.h`（`SENSECAP_URL`）改掉重新编译 → 彻底断开 Seeed 云（代价：官方 App 的配对/任务下发会失效，得自己接管）。

### L3 · 编译自己的固件（甜点区，解锁一切）

```powershell
# 本机已装 ESP-IDF v5.5（EIM 安装），激活方式：
. 'C:\Espressif\tools\Microsoft.v5.5.PowerShell_profile.ps1'

cd D:\DSH_workspace\watcher-mod\build\factory_firmware_mod
idf.py set-target esp32s3
idf.py -p COM6 flash monitor
```

> 仓库 README 写的是 IDF v5.1，最新 commit 声明兼容 IDF 6。v5.5 一般能过，个别 API 需小改。
> 本机 `C:\Espressif` 的工具链解压坏了（`cc1` 缺失），先跑 `eim fix C:\Espressif\v5.5` 修复。

拿到 dev 固件后立刻解锁这些能力：

```text
SenseCAP> taskflow -e                 # 导出当前任务流 JSON
SenseCAP> taskflow -i -f tf.json      # 从 SD 卡导入自己的任务流
SenseCAP> taskflow -i -j              # 从 stdin 粘贴 JSON（免拔卡）
SenseCAP> bsp i2cdetect 0             # 扫 I2C 总线上挂了什么
SenseCAP> rgb -r 255 -g 0 -b 0 -m 1   # 直接点灯
SenseCAP> record -t 5 -f a.wav        # 录 5 秒存卡
SenseCAP> vi_ctrl -s                  # 触发语音交互
SenseCAP> iperf -c 192.168.1.10       # 测 WiFi 吞吐
SenseCAP> ota -t 2 --url=http://192.168.1.10/factory_firmware.bin   # 无线自刷固件！
```

**`ota -t 2` 是隐藏王牌**：它走 `esp_https_ota` 且 `app_ota_any_ignore_version_check(true)`，等于「自己架个 HTTP 服务器就能无线升级自己的固件」，不用每次插 USB。

加一个新模块只要一个 C 文件（官方有完整教程 `docs/function_module_dev_guide.md`）：

```c
// main/task_flow_module/tf_module_mqtt_alarm.c
esp_err_t tf_module_mqtt_alarm_register(void) {
    return tf_module_register("mqtt alarm", "push event to local broker",
                              "1.0.0", &__g_module_management);
}
```

`main/task_flow_module/` 下任何 `.c/.h` 都会被构建系统自动扫进编译树，然后在 `app_taskflow.c` 的注册表里加一行即可。想做 `mqtt alarm` / `gpio alarm` / `telegram alarm` / `rtsp snapshot`，都是照抄 `tf_module_local_alarm.c`（最简）改 200 行的事。

### L4 · 换 AI 脑子（Himax HX6538）

- **只想换模型**：SenseCraft AI 上训练（或选现成模型）→ 任务流里引用 `model.url`，或命令行 `ota -t 0 --url=<xxx_int8_vela.tflite>` 直接下发。
- **想改 AI 固件**：源码在 `Seeed-Studio/sscma-example-we2`，用 `python-sscma` 或 `sscma_client` 的 WE2 flasher 刷。⚠️ 官方明确写了「不建议用户改动 Himax 固件」，刷之前先确认能回滚（img 已在仓库里）。
- **完全绕开 Himax**：用 `image analyzer` 模块把 OV5647 的原始帧直接 POST 给你的服务器做推理，Himax 只当摆设。算力放到你自己的机器上。

### L5 · 硬件层

- **Grove I2C / 2×4 排针**：源码里已经有 `main/sensor/sensor_sht4x.c`、`sensor_scd4x.c` 驱动 → 接温湿度/CO₂ 传感器，直接进 `http alarm` 的 `sensor_en` 字段上报。
- **UART2（GPIO19/20）**：接第二块 MCU 做执行器（继电器、舵机、门锁），协议见 L1。
- **2 个 GPIO**：排针上还有 2 根自由 GPIO，可做按键/干接点输入。
- **电源**：400mAh 只够优雅关机，想离线跑必须改电池或走 5V_IN 常供。背面 USB-C 只供电，别指望它通信。

## 4. 我建议先做的三个项目（按性价比）

### ① 「本地大脑」——隐私版 Watcher（1~2 小时）
装 `watcher_service` → App 里填 URL+Token → 拔掉外网验证还能识别。零固件改动，立刻见效。

### ② 「Watcher 当传感器」——UART 报警进自己的板子（半天）
App 里勾 UART 输出（JSON）→ XIAO/树莓派脚本读串口 → 触发你自己的动作（点灯、发微信、开继电器）。文档里连示例代码都给了（`sensecap_watcher_as_grove.md`，含 XIAO / 树莓派 / Jetson 三套）。

### ③ 「自建 dev 固件 + mqtt alarm 模块」（1~2 天）
编译 factory_firmware → 刷入 → 写 `tf_module_mqtt_alarm.c` → 事件推本地 Mosquitto → Home Assistant 自动化。做完这一步，这台设备就完全属于你了，云只是可选项。

## 5. 坑与红线

1. **`nvsfactory` 不能擦**（EUI/云端凭据）。已备份，别覆盖。
2. **Himax 侧能不碰就不碰**，刷坏了要用 `python-sscma` 走 COM5 救。
3. 量产固件与源码不同步（CLI 少了 6 条命令）→ 刷了自编固件后，官方 App 的部分功能行为可能变化，先小范围验证。
4. 编译参数必须带 `--flash_size 32MB --flash_mode dio --flash_freq 80m`，否则分区表越界。
5. `examples/openai-realtime/src/ui/*.c` 里单文件就有 12MB 的 LVGL 图片数组，编译慢、体积大；改 UI 时注意别把 12MB 的槽撑爆。
6. 换 `SENSECAP_URL` 等于自断官方云，务必先做完本地替代再切。
7. 电池只有 400mAh：调试时全程插 5V。
