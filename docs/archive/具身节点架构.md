# SenseCAP Watcher 作为具身智能终端节点 — 架构设计

> ⚠️ **本文前提已被推翻**：本文基于 **Seeed 官方工厂固件**（taskflow / image analyzer / http alarm）源码。
> 实机已确认跑的是 **小智 xiaozhi-esp32 v1.8.5**（分区表、`esp_app_desc`、端点、NVS 内容全部实测）。
> 请以 [小智具身改造.md](../小智具身改造.md) 为准；本文仅在把机器刷回 Seeed 固件后成立。

> 结论先说：**这台设备不需要刷固件，就已经是一个合格的"眼/耳/嘴/脸"瘦终端。**
> 量产固件里预留了 4 个可单独指向自己服务器的「本地服务」槽位，视觉分析模块就是你大脑的插口。
> ESP32 只负责反射弧——这一点它做得到，而且官方就是这么设计的。

---

## 1. 算力边界：先认清它到底能干什么

| 能力 | 实际实现 | 延迟量级 | 断网可用 |
|---|---|---|---|
| 看（检测） | Himax HX6538（M55 + Ethos-U55）跑 int8 视觉模型 | 50–150 ms | ✅ |
| 看（理解） | **本地做不到**，必须把 640×480 JPEG 甩出去 | 0.8–4 s | ❌ |
| 听（唤醒/录音） | ESP32 + 单麦 I2S，16k/16bit/单声道 | 本地 | ✅（但要自己接 ASR） |
| 说 | 喇叭播 PCM/MP3（`app_audio_player` 带 HMP3Decoder） | 即时 | ✅（音频得外部给） |
| 说（生成） | 本地做不到 | 200 ms–1 s | ❌ |
| 显示 | SPD2010 412×412 + LVGL，表情/画面 | 本地 | ✅ |
| 动手 | UART2(GPIO19/20) + Grove I2C + 2×GPIO | 本地，ms 级 | ✅ |

**分工原则**：ESP32 做「条件反射」，1 秒内必须完成的动作全在本地；需要"想一下"的事情全部外包。

## 2. 已存在的外联通道（不用改固件，全部实测于源码）

### 2.1 通道 A：`image analyzer` — 看→想→说 的闭环

设备自带模块，源码 `tf_module_img_analyzer.c`：

```
POST {你的URL}/v1/watcher/vision
Authorization: <你在 App 里填的 Token>
Content-Type: application/json

{"img": "<640x480 JPEG 的 base64>",
 "prompt": "画面前有人吗",          // 任务关注点
 "audio_txt": "有人来了",           // 任务名，会被当成播报文本
 "type": 0}                         // 0=RECOGNIZE 单次分析  1=MONITORING 持续监控
```

你的服务器回：

```json
{"code": 200,
 "data": {"state": 1,          // 1 = 需要提醒（下游才会被触发）
          "type": 0,           // 回显或改写
          "audio": "<base64 音频>",   // ← 设备直接拿去放！这是"嘴"
          "img":  "<base64 可选>"}}    // 可选：替换屏幕上显示的画面
```

关键逻辑（源码 line 415）：
- `type == 0`（RECOGNIZE）→ **必定**向下游发事件；
- 否则只有 `state == 1` 才发事件。
- 发出去的事件 = `图(大/小) + 推理框 + 音频 + 文本`，下游 `local alarm` 收到后：
  - `sound:true` 且播放器空闲 → **播你回的 audio**（`app_audio_player_mem`）
  - 同时按参数亮 RGB / 显示图 / 显示文字 / 持续 N 秒

**这条链路 = 摄像头 → 你的大脑 → 它开口说话。零固件改动。**

### 2.2 通道 B：`http alarm` — 报警代理

```
POST {你的URL}/v1/notification/event
{"time": "...", "text": "...", "image": "<base64>", "sensor": {...}}
```
字段开关：`time_en / text_en / image_en / sensor_en`，节流：`silence_duration`。

### 2.3 通道 C：`uart alarm` — 硬实时反射弧（给下位机）

115200 8N1，GPIO19(TX)/20(RX)。JSON 模式：

```json
{"prompt":"People detected","big_image":"<base64 jpg>",
 "inference":{"boxes":[{"x":100,"y":100,"w":50,"h":60,"score":0.8,"target_cls_id":1}],
              "classes_name":["person"]}}
```

二进制模式：`"SEEED"`(5B) + prompt + 大图 + 小图 + 推理类型 + 框表 + 类名表（见 `tf_module_uart_alarm.h`）。
→ 接 XIAO / 树莓派 / 下位机，**断网也能跑**：检测到人 → 开继电器/亮灯/报警，全程不经云。

### 2.4 这 4 个槽位是谁

`app_device_info.h` 里 `local_service_cfg_type1_t`（每项都有 `enable / url / token`，存在 NVS，App 或 MQTT/BLE 下发）：

| 槽位 | 谁在用 | 默认路径 |
|---|---|---|
| `CFG_ITEM_TYPE1_IMAGE_ANALYZER` | `image analyzer` 模块 | `/v1/watcher/vision` |
| `CFG_ITEM_TYPE1_NOTIFICATION_PROXY` | `http alarm` 模块 | `/v1/notification/event` |
| `CFG_ITEM_TYPE1_AUDIO_TASK_COMPOSER` | 语音造任务 | 语音链路 |
| `CFG_ITEM_TYPE1_TRAINING` | 云端训练 | — |

⚠️ 重要：任务流 JSON 里的 `url` 字段**不会**生效，host 来自这个 NVS 槽位（源码 line 488–515），路径是编译期常量。想换路径，改 `tf_module_img_analyzer.h` 里那一行 `#define` 重编即可。

## 3. 目标架构

```
                    ┌────────────── 断网也能跑（反射弧，<300ms）──────────────┐
  人/物 ──▶ OV5647 ──▶ HX6538 本地模型 ──▶ [ai camera] ──▶ [uart alarm] ──▶ 下位机/继电器
                                                                  │
                    └──────────────────────────┬───────────────────┘
                                               │ 只在"值得想一下"时才升级
                                               ▼
                                        [image analyzer]
                                               │ POST base64 JPEG
                                               ▼
                        ┌──────────────────────────────────────┐
                        │  网关 gateway.py  (跑在你的机器上)     │
                        │  · 存图 / 打日志 / 鉴权 / 节流          │
                        │  · 调 VLM → 决策(state) → TTS(audio)  │
                        └──────────────┬───────────────────────┘
                                       │ {"code":200,"data":{state,audio}}
                                       ▼
                          [local alarm] ──▶ 喇叭说一句话
                                       └──▶ 屏幕表情 + RGB
                                       └──▶ [http alarm] ──▶ 你的消息队列/HA/Telegram
```

**本质**：Watcher 是"身体"，网关是"脊髓"，模型是"大脑"。三者用 HTTP 解耦，任一层可替换。

## 4. 延迟预算（决定什么必须留在本地）

| 环节 | 耗时 | 说明 |
|---|---|---|
| 端侧检测 | 50–150 ms | HX6538，本地 |
| 抓帧 + JPEG + base64 | 100–200 ms | 640×480，约 30–80 KB |
| WiFi 上行（2.4G） | 100–400 ms | 实测受路由器影响大 |
| VLM 推理 | 0.4 s（本地 4090）/ 1–3 s（API） | **瓶颈**；官方 benchmark：RTX4060 4s，无显卡 4min |
| TTS | 0.2–1 s | 可流式优化 |
| 播放 | 即时 | — |
| **合计** | **0.8–4 s** | 所以"躲开挥手/有人靠近立刻亮灯"这类必须本地 |

节流阀门（都在任务流参数里，不用改代码）：
`silent_period.silence_duration`（默认 30s）、`conditions[].num`（人数阈值）、`output_type`、`shutter`、`time_period`。

## 5. 落地路线（三阶段，每阶段都有验收标准）

### 阶段一：打通「看 → 想 → 说」（今天，纯软件，零固件改动）

1. 跑网关：
   ```powershell
   cd D:\DSH_workspace\watcher-mod\embodied
   $env:WATCHER_TOKEN="mytoken"
   $env:OPENAI_API_KEY="sk-..."      # 不填则走 mock（回一段哔声，用来验证链路）
   python gateway.py
   ```
2. 手机 App → Watcher → 设置 → **设备 AI 服务** → 填 `http://<你电脑内网IP>:8710` + `mytoken`。
3. 在 App 里建一个任务：`ai camera`（人检测）→ `image analyzer`（prompt 写你要问的）→ `local alarm`。
4. **验收**：人走进画面 → 串口/日志里能看到 POST → 喇叭响（mock 是哔声，接上 key 就是人话）。
   `brain.jsonl` + `inbox/*.jpg` 里能看到每一帧和决策。

> 已用 curl 验证过契约：`code=200 / state=1 / audio=10728 字节 base64`，错 token 返回 401。见 `embodied/brain.jsonl`。

### 阶段二：给身体加"反射弧"（1 天）

- 任务流里加 `uart alarm`（`output_format=1`）→ 下位机/树莓派读 JSON → 做本地动作。
- 加 `local alarm` 的 `sound/rgb/img/text/duration` → 不看云也能给现场反馈。
- **验收**：拔掉外网，检测到人时本地仍亮灯/报警/驱动继电器，只有"说话"降级。

### 阶段三：让它有"存在感"（按需，要动固件）

| 想要 | 怎么做 | 代价 |
|---|---|---|
| 自定义 UI 表情（眨眼、看向、思考中） | LVGL + SquareLine Studio，412×412；`examples/factory_firmware/main/view/ui` | 要编译、刷机；图片数组很大，注意 flash 12MB 槽 |
| 真正的语音对话（全双工） | 参考 `examples/openai-realtime`（WebSocket 流式）或改 `app_voice_interaction.c` 的 talk host | 要编译；需自建 ASR/LLM/TTS 流 |
| 麦克风上行到自己的服务器 | 现在只有 `record`（存 SD）+ `vi_ctrl`（走官方 talk 服务）；自建需要写模块 | 一个 C 文件 + 编译 |
| 换视觉模型 | SenseCraft AI 训练 → `ota -t 0 --url=`；或 sscma-example-we2 | Himax 侧，官方不建议乱动 |
| 无线升级自己的固件 | `ota -t 2 --url=http://你的IP/factory_firmware.bin`（忽略版本校验） | 免插 USB，风险可控 |

## 7. 还没解决的硬问题（诚实清单）

1. **麦克风上行没有现成接口**：量产固件只把录音用于官方 talk 服务；想自己接 ASR，要么改 talk host（`CONFIG_TALK_SERV_HOST`）要么写模块。
2. **TTS 采样率（已澄清）**：`app_audio_player.c` 会自动嗅探 **WAV(RIFF/WAVE)** 或 **MP3(ID3 / 0xFF 帧同步)**，且发现 WAV 头里的采样率/声道/位深与默认不同时会**自动重配 I2S**（源码 `__is_wav` + `app_audio_player_stream_send`）。所以网关不必强制重采样；现在仍接 ffmpeg 转 16k 只是稳妥起见，可直接关掉。
3. **单帧上限**：`img` 是 640×480 JPEG base64，30–80 KB；长时视频流不现实，只能"事件帧"。
4. **没有长时记忆**：设备端只有 NVS/SD，记忆必须留在网关侧（brain.jsonl 就是雏形）。
5. **屏幕改版要刷机**：想让它"有表情"，必须编译 LVGL 资源，且 12MB 的 app 槽不算宽裕。
6. **全片 flash dump 未完成**：读取 32MB 时在高地址出现 `Corrupt data`，已改成分块 + 降速重试；即使失败也不影响回滚（官方 V1.1.7 全套 bin + nvsfactory 已在手）。

## 8. 一句话总结

**别把它当"小电脑"，把它当"带喇叭的传感器 + 带脸的执行器"。**
ESP32 那段代码你几乎不用碰——官方已经把它做成了一个可以被外部大脑驱动的 RTOS 外设；
你要写的全部，是一个几十行的 HTTP 网关，和一个愿意陪它说话的脑子。
