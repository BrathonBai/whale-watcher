## 0. 一句话结论

**Opus 链路两端都通了（设备解码 + 桥编码/协商/自适应），PCM 环从 576 KB 收到 120 KB，带宽需求从 48 KB/s 降到 16 kbps（≈2 KB/s，24 倍余量）；WiFi 侧锁 BSSID/扫描策略/连接日志落地；core dump + 栈水位 + 复位原因让"黑盒"有仪表盘。** 剩下的关键动作是：刷机（**这次要刷分区表**）→ 真机标定。

## 1. 改了什么

### 1.1 设备侧：Opus 解码（唯一治本项）

| 项 | 内容 |
|---|---|
| 解码器 | vendored [`esphome/micro-opus 0.4.1`](../firmware-v2/components/micro-opus/)（libopus + Xtensa LX7 DSP 优化；伪栈/状态放 PSRAM） |
| 数据路径 | `WS 收包任务` 只 memcpy 裸包 → 包环 64×1275B（PSRAM）→ `adec` 任务（prio 7，栈 8KB）`opus_decode` → 现有 PCM 环 → I2S |
| 协议 | hello：`codecs:["pcm","opus"], opusRate:16000`；下行 `audio.codec:"opus"|"pcm"`（缺省 pcm）；opus 每 WS 帧=一个 20ms/16k mono 裸包；`audio_end` 不变；pong 带 `bufMs/underruns/reconnects/rssi/codec` |
| 内存 | PCM 环 **576 KB → 120 KB**（2.5 s）；新增包环 ~80 KB + 解码缓冲 5.6 KB + 伪栈 120 KB（懒分配）+ 状态 30–50 KB；**PSRAM 净减 ~193 KB**；内部 RAM +8 KB（adec 栈） |
| 失败策略 | 启动 PSRAM 预检（320 KB）→ 创建/任务任一失败 → ERROR + **回退 PCM**（hello 只报 pcm）；运行期丢包/解码错/写环丢弃全部计数 + 限频日志，不静默 |
| 兼容 | 老桥/老设备都走 PCM 原路径；桥侧可 `audioCodec=pcm` 强制回退 |

### 1.2 桥侧：Opus 编码 + 协商 + 自适应码率

- **编码**：`lib/opus_encode.js`，ffmpeg/libopus `pipe:0→pipe:1` 出 Ogg，再自写增量 Ogg page 解析拆裸包（处理 lacing 255 / 跨页 continued / 头包跳过 / 1..1275B 校验）；错误码显式（`OPUS_UNAVAILABLE/SPAWN_FAILED/FFMPEG_FAILED/TIMEOUT/PARSE/EMPTY`），失败**显式回退 PCM** 并写 `/api/state.audio.lastEncodeError`。
- **协商**：hello 有 `codecs` 才走 opus；`audioCodec: auto|opus|pcm`。
- **自适应**：`lib/audio_profile.js` 按最近 6 条 pong 的 `bufMs` 选档：**≥120ms→24kbps / ≥60ms→16kbps / 差→8kbps / 连续差或 60s 无 pong→回退 PCM**；HOLD 防抖、编码失败冷却 60s；**每段回复只选一次档位**，`/api/diag.audio` 输出 tier/reason/lastSwitch/lastFallback/lastEncodeMs/lastEncodeError。
- **本地台词包 v2**：缓存键含 codec/bitrate/engine/voice/model/speed/guidance，旧 v1 PCM 缓存自动失效；命中按 20ms 节奏重放。
- **诊断面板**：`/api/state.audio`、`/api/diag.audio`、桥日志 hello 能力、panel 音频诊断行。

### 1.3 WiFi 稳定性（四连改的落地情况）

| # | 项 | 状态 |
|---|---|---|
| 1 | 关省电 `WIFI_PS_NONE` | ✅ 之前已做（本轮未改） |
| 2 | 缓冲参数（STATIC_RX/DYNAMIC_RX/RX_BA_WIN） | ⏸ **本轮不启用**：内部 SRAM 是绑定约束，必须先看 v2 自己的 `[mem]` 日志；候选行已写在 `sdkconfig.defaults` 注释里 |
| 3 | 锁 BSSID / 扫描策略 | ✅ `HUB_WIFI_BSSID`/`HUB_WIFI_CHANNEL` 可选宏（换网 SSID 不匹配自动跳过）、连接前定向 scan、同 SSID 多 BSSID 只 warn 一次并给候选、关联日志带 bssid/channel/rssi、未锁时 ALL_CHANNEL+BY_SIGNAL |
| 4 | LWIP 窗口 | ⏸ 同上（未测量内部 RAM 前不动；候选行已备） |

### 1.4 可观测性 / 稳定性小项

- **core dump 落 flash**：`partitions.csv` 尾部新增 `coredump` **128 KB**（`0x1a00000`，原有 7 个分区 offset/size 一个没动）；sdkconfig 开 `ENABLE_TO_FLASH/ELF/CRC32/CHECK_BOOT`、关 `LOGS`（省 ~5KB）、栈 1792。
- **开机第一屏**：固件版本/协议号、`__DATE__/__TIME__`、IDF 版本、Flash 配置、`esp_reset_reason()`（异常复位打 ERROR）。
- **栈水位**：ui/net 任务每 60s 打 `uxTaskGetStackHighWaterMark` + 内部 free/largest。
- **说话降帧**：Speak/Happy 时渲染 100ms→200ms（5fps），只切换时打日志；帧缓冲仍在 PSRAM（332KB 内部 RAM 放不下）。
- **未做**：camera deinit（`sscma_client` 无安全 API，强改会让 BSP 静态 handle 悬垂）；PM 动态调频；AEC/VAD；I2S DMA 调参；按键语义（下一轮）。

## 3. 刷机步骤（**本轮分区表变了，必须刷表**）

产物：`%LOCALAPPDATA%\hubdev\v2\build\hub_v2.bin`（4,946,432 B）、`partition-table.bin`（3072 B）。

```powershell
# 0) 先备份当前分区表与 app（回滚用）
#    COM6 @921600；按你机器实际串口改
$env:IDF_TOOLS_PATH='C:\Espressif'; & 'C:\Espressif\v5.5\esp-idf\export.ps1'
python -m esptool --chip esp32s3 -p COM6 read_flash 0x8000 0x1000  backup\partition-table-old.bin
python -m esptool --chip esp32s3 -p COM6 -b 921600 read_flash 0xe00000 0x500000 backup\ota1-old.bin

# 1) 刷分区表（0x8000）+ 新 app（ota_1 @0xe00000，保持 A/B 不变）
Set-Location "$env:LOCALAPPDATA\hubdev\v2"
python -m esptool --chip esp32s3 -p COM6 -b 921600 --before default_reset --after hard_reset `
  write_flash 0x8000 build\partition_table\partition-table.bin `
              0xe00000 build\hub_v2.bin
```

> 只刷 app 不刷表也能启动（coredump 会 warn 一次、不产生 dump）；但既然本轮加了 coredump，建议一起刷表。
> 回滚：刷回 `backup\partition-table-old.bin` + `backup\ota1-old.bin` 到原偏移。

## 5. 风险 / 回退开关（真机留意）

| 风险 | 表现 | 回退 |
|---|---|---|
| micro-opus 伪栈懒分配失败 | `pseudostack overflow` 后 abort/重启 | 先 `audioCodec=pcm`；PSRAM 够的话把 `CONFIG_OPUS_PSEUDOSTACK_SIZE` 提到 240000 重刷 |
| 2.5s 环不够抗会场抖动 | `音频收尾` 时 underruns 增加、断音 | 提高 `kStreamBufferMs`（如 4000）重刷；或桥侧降档 8kbps |
| `Flush()` 在 WS 任务里最坏 2s | pong 延迟/偶发断连，日志 `Flush 超时` | 若现场出现，改成"解码任务排空后回调"（下一轮） |
| ffmpeg 首句编码耗时 | 首字延迟 +0.3–0.8s（估） | `audioCodec=pcm`；或把固定句预编码进 voicepack |
| coredump 128KB 是否够 | dump 失败日志 | 分区改 256KB（需重刷表） |
| 自适应阈值未标定 | 档位抖动/降档过猛 | `audioAdaptive=false` 锁 `opusBitrate=16000` |

## 7. 刷机实测（2026-11-03 21:00 前后）

### 7.1 刷写内容与两个现场坑

- **otadata 无效**（`seq=1`、`state=0xFFFFFFFF`）→ bootloader 回落到 **ota_0（0x200000）**，不是之前假设的 ota_1。
  实际刷的是：分区表 `0x8000` + app `0x200000`。备份在 `%LOCALAPPDATA%\hubdev\backup\2026-11-03\`。
- **坑 1（已修，commit `bf3d726`）**：没插 TF 卡时 BSP 的 `bsp_sdcard_init()` 内部是
  `ESP_ERROR_CHECK(esp_vfs_fat_sdspi_mount(...))`，失败直接 abort → **启动循环**。
  改为 `storage.cc` 自己挂载（失败只 warn，卡不在就跳过），真机复测启动正常。
- **坑 2**：设备 NVS 里残留旧网络 `TT-W8BQ`（`nvs_open("wifi")` 优先级高于 `wifi_local.h`），
  新 WiFi 配了也不生效。已擦除 `nvs` 分区（`0x3b000, 0xd2000`，只存 WiFi 凭据），
  备份 `nvs-old.bin`；擦后由 `wifi_local.h`（新 SSID + 桥地址）接管。
