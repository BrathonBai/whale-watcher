## ① 结论摘要（≤10 行）

1. **技术链路已经"真机可跑"，但产品化只完成了一半：设备端功能在，产品定义/配网绑定/隐私合规/内容授权/升级售后五块几乎为零。现在能卖的是"极客开发套件"，不是"桌面陪伴大肥鱼"。**
2. 用户旅程 8 环里，终端用户今天能独立走通的只有 **"上电"** 和 **"本地摸头"**；**配网、绑定、首聊、售后**四环断（配网=改头文件重刷，绑定=编译期桥地址/UDP 广播）。
3. **称呼/人设 12 处冲突**：对外"鲸鲸／大肥鱼／鱼"，运行态"蓝蓝"，素材"shenshen"，音色"大肥鱼·迷糊版"；且 systemPrompt 把桌面设备写成"**戴在主人身上的小设备**"——第一句话就与产品形态矛盾（P0）。
4. **首聊体验不达标**：TTS 整段合成 5.3–6.1 s + 预缓冲 1 s + ASR 1.2 s，估算"按下→听到第一声"约 **8–10 s**，且播放中不能打断（P1，首版必须压到 P50≤5 s）。
5. **隐私承诺与实现不一致**：对外说"画面不出设备、只发一个浮点数"，实现是拍照 JPEG 上桥落盘、路径交给大脑、50 段用户录音留在 PC、局域网任何人可 `GET /shot.jpg`（P0）。
6. **IP 授权无凭据**：角色素材 shenshen（2651 帧/137 MB）无授权文件，Breeze 音色"大肥鱼·迷糊版"商用条款未核实——不解决不能卖（P0）。
7. **商业模型空缺**：无 BOM 报价、无单台云成本、无定价/渠道/售后；估算现成 Watcher 整机成本约 ¥500–720，直接转售毛利仅约 20–30%；自研外壳 BOM 估算 ¥160–260，但需 8–20 万模具与 3–6 个月（全部为估算）。
8. 证据不支持"现在能卖"：路演文档自己写"**不是产品、不谈商业、现在不能商用**"；20 人内测方案与验收基线尚不存在。
9. **最关键判断：先收敛"卖什么"（建议：桌面 PC 配件 + 自带大脑/BYO key，先内测 20 台），再补配网/绑定/首聊/隐私/升级五项首版能力；形态未定前不要开模、不要上云端账号体系。**
10. 固件/桥/设计资产很扎实（见 §④），**不要重做**；首版把力气全部放在"消费品化"的 5 个断点上。

### 维度 1 · 产品定义是否收敛

#### 1.1 结论

**没有收敛，而且方向本身就是矛盾的。** 同一件东西在仓库里至少有四种"是什么"：

| # | 定义 | 出处 | 矛盾点 |
|---|---|---|---|
| D1 | "感知层→模型层链路的可行性验证"（不是产品） | `路演/路演讲稿.md:3,152,159-168`；`路演/评委Q&A-预案.md:3` | 与"要卖的产品"直接冲突；文档明确说"不谈商业、现在不能商用" |
| D2 | "桌面陪伴大肥鱼（鲸鲸）" | `路演/传单/preview-front.png`（"她不在窗口里 她在桌面上"） | 这是产品叙事，但没有 PRD/用户画像支撑 |
| D3 | "Hub runtime 授权 + 行业交付 + 云端订阅"（B2B 平台） | `路演/评委Q&A-预案.md:76-78`（B1） | 与消费级硬件售卖是两套商业模式 |

**给谁**：没有用户画像/人群/规模/场景文档。唯一接近的是 Q&A 里的"20 个愿它待在桌上的真人"（`评委Q&A-预案.md:126`）和伙伴形态里的"坐在桌前"（`伙伴形态-可行性.md:103-107`）——这是验证计划，不是目标用户定义。

**解决什么**：`docs/伙伴形态-可行性.md` 把机制讲清了（存在感/主动性/反应速度/记忆/身体语言），但**没有一句话回答"用户为什么买它而不是小智、智能音箱、手机 App"**。Q&A 有一句"桌上第三只眼"（`评委Q&A-预案.md:62`），但产品页/传单没有用这句。

**和"会说话的表情包"/智能音箱的差异**：技术上差异成立（DSH 会话 + 工具 + 人格 + 摄像头），但**用户感知不到**：没有主动开口、没有记忆召回、没有唤醒词，今天用起来就是"按一下、等 8 秒、听一句、看字幕"——比智能音箱还少（音箱至少免按键）。

### 维度 2 · 用户旅程与配对

#### 2.1 结论

**旅程断在四个地方，且都不是"再写两天代码"能补的：**

1. **配网**：产品菜单直接让用户"改 wifi_local.h 重刷"（`app_ui.cc:389`）。真实可用路径是串口 `>wifi` 或编译期头文件；`net_wifi.cc:296-325` 的凭据优先级里没有"用户界面"。历史文档里 AP 配网向导（`192.168.4.1` + SSID 列表 + 二维码）只设计过、没实现（`docs/会话整理与sw核查-2026-10-30.md:18`）。
2. **绑定**：没有账号/设备身份/二维码；设备找桥靠 UDP 广播（`bridge_find.cc`）或编译期 `HUB_BRIDGE_URL_LOCAL`（`app_main.cc:156-161`）。换一台电脑/换 IP 都需要碰串口或重刷。
3. **首聊**：能用，但"慢"和"不能打断"是硬伤（见 2.2）。而且端到端没被验证过：交接文档只验到"上行字节数"（`交接-鲸鲸-v2-2026-10-31.md:24`），审计时运行态也没有一次 voice 事件。
4. **故障/售后**：断网无屏显、无恢复出厂（`ClearWifiAndReboot()` 只有声明 `board_watcher.h:78`，全仓无实现/调用）、换网要擦 NVS、救砖要 32 MB 全片镜像。

#### 2.2 关键环节深挖

**A. 首聊到底多慢（估算，基于实测分项）**

| 段 | 实测/配置 | 来源 |
|---|---|---|
| ASR | SenseVoice 常驻，2 s 音频 1.2 s 出字 | `docs/TODO-后续升级.md:45` |
| LLM 首字 | 0.3–1.5 s | `docs/伙伴形态-可行性.md:51` |
| TTS | **整段合成 5.3–6.1 s**（当前 `breezeStream=false`） | `docs/TODO-后续升级.md:43`；运行态 `/health.tts.stream=false` |
| 预缓冲 | 1000 ms | `bridge/lib/config.js:52-54`；运行态 config `ttsPreBufferMs=1000` |
| **合计（首音）** | **约 8–10 s** | 估算：1.2 + 1.0 + 5.5~6.1 + 1.0 |

> 这是"按一下、说完、等 8–10 秒才听到第一声"。对陪伴产品是致命的——第一次使用就决定退货。

**B. 播放中不能打断**

单麦无 AEC，播报时麦克风被自己的喇叭淹掉（`docs/伙伴形态-可行性.md:53,182`；`评委Q&A-预案.md:24-26`）。当前也没有"按键停止播放"：`TODO-后续升级.md:128` 明确"播放中按键不会停"。而固件 `app_ui.cc:401-415` 的按键语义只有"开始录音/停止并发送"。

**C. 断网时用户看到什么**

- WiFi：后台 5 s 重连（`net_wifi.cc:227-230`）。
- WS：1–10 s 指数退避，连败两次后 UDP 广播找桥（`ws_client.cc:383-442`）。
- 屏幕：**没有离线态**。设计稿有 `offline`（`design/out/contact_sheet.png`），固件只把 LED 置错误色（`app_ui.cc:237,347`）；录音时若桥断，会"本地回放代替"（`app_ui.cc:351`）——用户会以为它在敷衍。
- 恢复：若 NVS 里是旧网络，会连旧网、新配 WiFi 不生效（`迭代-2026-11-03-总结.md:140-142`），需要工程师擦 NVS。

**D. 配对/绑定现状**

- 无账号体系；桥 HTTP 面板 `panelToken` 为空时"动作接口只认本机"（`bridge/lib/index.js:561-562`、`http.js:61-72`），也就是说**多台设备/家人共用没有身份概念**。
- 只读接口对局域网**完全免鉴权**：`/health`、`/api/state`、`/events`、`/panel`、`/shot.jpg`（`http.js:194-217`）。这意味着同一 WiFi 下任何人能看设备最近一张照片——隐私问题，见 CMP-01。

### 维度 4 · 成本与定价

> 本节全部为**估算**（无供应商报价、无云账单实测）；算法与假设写明，便于复核。

#### 4.1 结论

- 现成 Watcher 整机按官方零售价采购，单台成本约 **¥500–720**（$69–99，内部文档，需复核）；若零售定价 ¥699–899，毛利约 20–30%，**不足以覆盖退货/客服/认证摊销**。
- 自研/改模后 BOM 估算 **¥160–260**（1k 量），加上制造/良率/认证摊销约 ¥220–330；零售 ¥499–699 才有健康毛利。但前提是"外壳+认证+供应链"先解决。
- 云端单机月成本**未实测**；按用量估算 ¥5–17/月/台（TTS 为主），若用 PC 本地 ASR + 用户自带 LLM key，可接近 0——这正是首版最省事的模式。

### 维度 5 · 认证与合规

#### 5.1 结论

**合规是当前最大的"看不见的 P0"。** 全仓 grep `隐私/用户协议/保修/说明书/CCC/SRRC/FCC/CE/UN38/RoHS` 只命中工程文档里的零星词（如 `CC` 是固件填充值），**没有任何合规文档、隐私政策、用户协议、认证计划**。

同时存在**对外承诺与实现不一致**：

| 对外说法（路演） | 实现（运行态/代码） | 证据 |
|---|---|---|
| "画面不出设备，出设备的只有一个浮点数：变化量"（`评委Q&A:94`） | 拍照 JPEG 经 WS 上行 → 桥落盘 `workspace/images/` → 把文件路径附加给大脑（`index.js:322-323`）；`/shot.jpg` 局域网免鉴权可读（`http.js:205-217`） | 代码 + `/health.storage`（images 1 file） |
