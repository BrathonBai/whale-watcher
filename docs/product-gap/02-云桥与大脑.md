## 0. 结论摘要（10 行）

1. **形态判定**：当前是"开发者可演示原型"。大脑 100% 长在**一台 Windows PC 上的 DSH 桌面进程里**（插件进程内 + 本机 Python ASR + 本机 ffmpeg + 用户自备 Breeze key + DSH 账号），普通用户装不了、也修不了。
2. **有 8 个 P0**（不解决不能量产）：无消费者安装路径（CB-01）、配网/服务器地址编译期写死（CB-02）、PC 单点即大脑（CB-03）、无账号/设备绑定（CB-08）、断云即哑（CB-11）、`WS /device` 无鉴权（CB-35）、Breeze key 明文单 key（CB-36）、无 OTA（CB-42）。
3. **语音"能听清"已达标**：常驻 SenseVoice ASR 实测 **73–419 ms/句**（`bridge-2026-11-03.log:38,48,269,294,341,353`），是当前链路里唯一达标的环节。
4. **"开口快"远未达标**：TTS 整段同步合成（`breezeStream=false`）实测合成 **2.4–5.5 s**、尾延迟 **16.8 s**（`:255`），叠加 LLM 轮 3.2–7.6 s、预缓冲 1 s → **首音 p50≈7 s、尾部>20 s**；目标 2.5 s。
5. **核心设计没跑起来**：默认 `brain=session`（设备有自己的 DSH 会话）在当前宿主上**建会话失败**——`bridge-2026-11-04.log:16`「宿主没有 sessionController.create」，每轮**静默降级 llm**（无工具、无会话记忆）；而 `/health.brain.effective` 在首轮失败前仍显示 `session`，会骗人（CB-06）。
6. **人格层不在产品链路**：`profile/package.json` 的 bundles 里**没有** `dsh-persona`（只有 junction），persona `state.json` 停在 **2026-11-01 10:45**、桥日志 0 次 persona → 12 条伙伴行为**没有一条完整闭环**（CB-20~22；3/5/8 仅有零件：语音/拍照/表情）。但 persona 代码完整、零依赖、有测试，**可直接复用上云，别重写**。
7. **已具备的硬资产不要重做**：v2 契约单一事实源 + 能力门控、Opus 下发（2 KB/s，24× 余量）、1 s 预缓冲、自适应码率、`/api/diag`、配置来源可见、（CSRF 已修）、10 套测试（本次实测 7 套 0 fail）。
8. **安全是量产硬门槛**：`WS /device` 任意 LAN 主机可顶掉真设备（`ws.js:162-181` 无任何鉴权）；只读面含照片/绝对路径对 LAN 开放；Breeze key 明文在 `plugins-data/embodied-bridge/config.json`（历史 P0 至今未闭环，本次审计读取已再次暴露 → **应立即轮换**）。
9. **迁移判断**：大脑侧 **≈90% 必须迁到云/服务端**（设备网关、ASR、TTS、LLM 编排、人格/记忆/主动、账号/绑定/计费、OTA、遥测）；PC 只保留"可选桌宠/桌面助手"。设备侧协议可不变，改 **URL + 设备 token + 配网 + OTA + TLS** 即可。
10. **排期**：云端 MVP 3–4 周（含固件一次刷机）→ 账号/绑定 + OTA + 遥测 4 周 → 人格/记忆/主动 3 周 → 计费/合规/加固 3 周；最大外部依赖是 TTS 供应商商务与国内可达性（Breeze 为单点）。

### 1.3 `reconnects=394` 是什么意思（按要求核对代码，不下错结论）

- 该数字**不是桥的计数器**，是设备在 `pong` 里自报的固件统计：`{"t":"pong",...,"reconnects":394,...}`。
- 固件定义：`ws_client.h:12-22` `struct Stats { int connects; int disconnects; ...; int reconnects; }`，`ws_client.cc:46` `Stats s_stats;`（**静态、从不清零**）。
- 自增点只有三处：连接失败重试 `ws_client.cc:424`、握手失败 `:434`、一次会话结束（正常/异常断开）`:442`。
- 桥侧只把它当诊断透传/展示：`device.js:297-307` 收进 `lastDiag/pongHistory`；`audio_profile.js:99` 只取最后一条展示；**没有任何阈值/告警/重置逻辑**。
- 判读：本连接内 394 **恒定不变**（连续 10 条 pong 都是 394）→ **不是"现在每秒重连"**；它是"设备本次上电以来的累计重连次数"。394 说明历史链路不稳（换网/路由器/会场 2.4G 都记录在案），但**不能**单凭它判当前故障；需要设备 uptime 才能算"每小时重连率"。
- 建议（P2）：桥侧加"reconnects 增速 > N/小时"告警；固件 pong 补 `uptimeMs`，否则这个数字永远无法归因。

## 5. 排期建议与依赖（含"哪些必须从 PC 迁到云"的判断）

### 5.1 迁移判断表（核心结论）

判断原则：**凡是"用户环境里的运行时依赖"都必须迁走；凡是"只有我们自己的机器才有的东西"都不能当产品依赖。**

| 能力 | 现在在哪 | 产品化必须迁到哪 | 理由 | 改动面 |
|---|---|---|---|---|
| 设备接入（WS/网关、设备鉴权、多设备路由） | PC 上的桥进程（`0.0.0.0:7788`） | **云网关**（wss + 设备证书/token + 按设备路由） | PC 不可常开；LAN 明文/无鉴权不能卖 | 云新写；固件改 URL+token+TLS；协议可不变 |
| ASR（SenseVoice 常驻） | 用户 PC：Python venv 91 MB + 模型 1.23 GB + `asr_server.py` | **云端 ASR 服务**（流式，按需扩容） | 安装不可行；模型升级要逐台；PC 性能差异 | 云端新写；桥/网关调用云端 ASR；固件不变 |
| TTS（Breeze 整段） | 用户 PC 用用户/开发者的 key 调 `api.breeze.blue` | **云端 TTS 服务 + 供应商抽象**（密钥服务端、流式、可切供应商） | key 不能下发；单供应商/可达性不可控；流式才能达标 | 云端新写；桥的配音/推流逻辑搬云端 |
| LLM | DSH 桌面 + `deepseek-account` 登录；`session`/`llm` 两种接法 | **云端 LLM 网关**（OpenAI 兼容、按租户配额、内容审核前置） | 不能要求用户登录 DSH；要能换模型/计费/风控 | 云端新写；`brain.js` 的会话/降级逻辑重写为云端编排 |
| 对话编排/会话状态 | bridge 进程内存 + DSH 会话 | **云端会话服务**（每设备/每用户会话、上下文、超时、工具调用） | 多设备/多用户必须集中；PC 崩溃不丢会话 | 把 `brain.js` 逻辑搬云端（保留契约与降级策略） |
| 人格/情绪/记忆 | persona 插件（本地 JSON，未加载） | **云端人格服务 + 持久记忆库**（摘要/召回/画像） | 记忆要跨设备跨重装；本地 JSON 不能多设备共享 | persona `engine/memory/voice/lines` 迁云端；设备只做表情/语音渲染 |
| 主动开口/定时任务 | persona `setInterval`（未加载） | **云端调度器**（按用户时区/静默期/额度） | 设备离线/PC 关机也要能算出"该说话了"；规则集中可调 | 云端新写；设备只执行"说/表情" |
| 设备管理/账号/绑定 | 无 | **云后台**（用户、设备、绑定、固件版本、在线、远程配置） | 售后/计费/召回的基础 | 新写 |
| OTA | 无（USB 刷机） | **云 OTA 服务**（签名、灰度、回滚、断电保护） | 卖出去的设备必须能远程修 | 固件加 `esp_ota` + 云端新写 |
| 计费/额度/审计 | 无 | **云平台** | 商业闭环与合规 | 新写 |
| 内容包（台词/音色/动画/人设） | 硬编码/固件内嵌/本地缓存 | **云内容平台**（版本/灰度/回滚下发） | 运营迭代不能靠发固件 | 新写；桥/设备加内容包加载 |
| 观测/日志/告警/崩溃 | 本地日志 + `/api/diag` + 串口 coredump | **云遥测**（指标/日志/崩溃/告警） | 客服/质量/迭代的前提 | 桥/固件加上报；云端新写 |
| 桌宠（dsh-pet）/DSH 桌面助手 | 用户 PC | **可留在 PC（可选增强）** | 它是"PC 场景"的增值，不是设备必需；不能反过来成为设备依赖 | 保留；与云端账号打通即可 |
| 本地台词包/兜底音效 | 设备内嵌 + 桥 voicepack | **留在设备/桥（离线兜底）** | 断网时唯一能出声的东西；必须本地 | 固件/桥保留并扩充到 ≥10 句固定兜底 |

**结论**：桥的"业务逻辑"（契约、状态机、音频策略、降级、工具）**可以整体搬进云端服务**，协议与设备侧基本不动；真正要重写的是"宿主/账号/鉴权/存储/调度/计费/OTA"这些产品骨架。PC 端从"大脑"降级为"可选桌面客户端"。

### 5.2 分阶段排期（含依赖与 Gate）

| 阶段 | 周期 | 内容 | 依赖 | 出门 Gate（验收） |
|---|---|---|---|---|
| **S0 云端 MVP** | 3–4 周 | 云网关（wss+设备 token）+ 云 ASR/TTS/LLM + 现有桥逻辑容器化；Breeze key 上服务端并轮换；设备端改 URL/token（一次刷机）；离网兜底≥10 句 | 固件改 URL/token/TLS；TTS 供应商商务；云端账号/环境 | 家庭网络下真机连续 3 天可用；首音 p50≤3 s（过渡目标）；断网 3 s 内有兜底音；密钥 0 明文 |
| **S1 账号/绑定/OTA/观测** | 4 周 | 账号登录、扫码绑定/解绑/转让、设备管理后台、OTA（签名/灰度/回滚）、遥测（在线率/延迟/错误码/崩溃）、远程日志（脱敏） | S0 完成；固件 OTA 分区/签名；App 或 Web 配网页 | 新用户自助开箱（配网+绑定≤15 min）；远程升级成功率≥99%；客服可 1 个页面定位单设备问题 |
| **S2 人格/记忆/主动/内容** | 3 周 | persona 引擎上云（情绪/精力/连续天数）、记忆库+每日摘要、主动开口调度、内容包（台词/音色/人设）下发、多设备同账号 | S1 完成；数据模型；内容编辑后台 | 行为 4/5/8/11 可验收（主动开口、拍照问答、情绪、诚实边界）+ 跨天记忆可引用；1 天主动开口≥2 次且可静音；内容包可灰度。视觉/唤醒类（1/2/3/6/9）依赖固件人检测/唤醒词，另立轨（不在本排期） |
| **S3 计费/合规/加固** | 3 周 | 套餐/额度/支付/账单、审计、隐私（同意/导出/删除/儿童模式）、安全加固（渗透测试、密钥管理、WAF/风控） | S2；法务/隐私文本；支付渠道 | 可收费；渗透测试 0 高危；隐私评审通过；单用户日额度与超限行为上线 |

> 关键路径：**S0 的固件改动（配网/OTA/TLS/设备 token）与云端必须并行**，否则 S1 无法验收。建议 S0 就一次性把固件"产品化三件套"做完（配网 + TLS + 设备 token + OTA 客户端），避免二次刷机。

### 5.3 关键依赖与风险

1. **TTS 供应商（最高外部风险）**：Breeze 单点、国内可达性不稳定（`tts_breeze.js:89-130`）、无备用；需在 S0 前完成商务/备选（至少两家）+ 国内节点评估。
2. **固件一次刷机窗口**：配网/OTA/TLS/token 都要动固件；v2 目前只有 USB 刷机与"ota_0 单槽在用"的历史（`小智具身改造.md:29-32`、`落实清单.md:17-32`），量产前必须把 A/B + 回滚做扎实。
3. **成本模型未知**：Breeze/LLM 单价不在仓库内，且当前**无计量**（CB-13）；S0 必须先把 tokens/字符/耗时埋点做出来，否则无法定价。
4. **隐私合规**：摄像头+麦克风+儿童场景=高风险；需在 S0 就确定数据流（哪些上云、留存多久、第三方清单），否则 S2 返工。
5. **DSH 去依赖**：产品不能要求用户装 DSH；桌面端保留为"可选增强"。这意味着 `brain.js` 的 `session/llm` 双接法要重写为云端编排（但契约/降级策略可保留）。
6. **组织风险**：当前桥/固件/persona 都是"一个人 + 文档"维护；无 CI、无值班、无版本策略（CB-47）；量产前至少要补 CI、发布流程、值班手册。

### 5.4 明确不做（范围纪律）

- ❌ 不把 ASR 大模型塞进 ESP32-S3（算力/内存都不够；`docs/平台选型…` 已论证）。
- ❌ 不保留"用户 PC 装 Python + 模型"的安装形态（CB-01 不解决就不发版）。
- ❌ 不把 Breeze key 下发给客户端（CB-36 红线）。
- ❌ 不在单设备/单用户假设上直接量产（先明确产品边界，CB-09）。
- ❌ 不为了压延迟去掉预缓冲/偶数帧对齐（会回到"卡顿/噪声"）。
- ❌ 不在无 OTA 的情况下发货（CB-42 红线）。
