# 这台设备到底是什么 —— 32MB 全片镜像取证

> 起因：怀疑手上这台不是"可开发版"。结论先给：**硬件是 sensecap-watcher，外设齐全；
> 但固件身份带测试/标定标记，不像量产后激活过的零售单元。**

## 为什么不用 REA 反汇编

| 路径 | 结果 |
|---|---|
| 原生反汇编（Ghidra/Hopper） | ❌ ESP32-S3 是 **Xtensa**，REA 支持 x86/x86_64/arm/arm64/mips/riscv/powerpc/6502，不含 Xtensa |
| `inspect_firmware_regions`（binwalk） | ❌ 返回 `capability_unavailable`：该集成要求 Linux + `REA_BINWALK_COMMAND` |
| `extract_firmware`（unblob） | ❌ 同上，Linux only |

所以改用**结构取证**：分区表、app 描述符、NVS、模型分区、字符串。这几样恰好是能回答
"这是什么设备"的证据，而且比反汇编更直接。

## 证据

### 1. 分区表（@0x8000，字段偏移 magic 是 2 字节 0xAA50）

| # | 名字 | 类型 | 偏移 | 大小 |
|---|---|---|---|---|
| 0 | nvsfactory | data/nvs | 0x009000 | 200 KB |
| 1 | nvs | data/nvs | 0x03b000 | 840 KB |
| 2 | otadata | data/ota | 0x10d000 | 8 KB |
| 3 | phy_init | data/phy | 0x10f000 | 4 KB |
| 4 | **model** | data/spiffs | 0x110000 | 960 KB |
| 5 | ota_0 | app/ota_0 | 0x200000 | 12288 KB |
| 6 | ota_1 | app/ota_1 | 0xe00000 | 12288 KB |
| 7 | — | MD5 校验项（正常结束） | | |

→ **A/B 双槽 + 独立的 model 分区**，是小智那套分区的标准形态。

### 2. app 描述符（@0x200000 + 0x20，魔数 0xABCD5432）

```
project_name = "xiaozhi"
version      = "1.8.5"
idf_ver      = "v5.4.1"
编译时间      = Aug  8 2025  17:51:16
```

### 3. model 分区内容

```
头部 01 00 00 00 "wn9_nihaoxiaozhi_tts" ...  + "wn9_data" "wn9_index" "_MODEL_INFO_"
```

→ 唤醒词模型 **WakeNet9「你好小智」**，随固件烧在 SPIFFS 里。我们要的语音唤醒**不用重训、不用下载**。

### 4. 字符串（app 区）

```
sensecap-watcher          sensecap-watcher/sensecap_audio_codec.cc
SensecapAudioCodec::Read  SensecapAudioCodec::EnableInput
spd2010_draw_bitmap       SSCMA client            SKU=%s
XIAOZHI_STATE_EVENTS      xiaozhi/ota/
```

→ 固件是给 **sensecap-watcher** 这块板编的，而且**带输入通道代码**（Read/EnableInput），
说明出厂固件本来就驱动 ES7243E 麦克风——我们读不到声音不是"这版没麦克风"。

### 5. NVS 里的身份

```
uuid        = 8d28a727-e347-43ab-b0f5-80377f7f6f17
ap.ssid     = Xiaozhi-ACB1          （MAC 90:70:69:11:ac:b1 的 AP 名）
client_id   = ID_test@@@90_70_69_11_ac_b0@@@8d28a727-e347-43ab-b0f5-80377f7f6f17
cal_data / cal_mac / cal_version     （出厂标定记录）
board
```

`client_id` 的 **`ID_test`** 前缀 + `cal_*` 标定记录 → 这台走的是**测试/标定流程**的身份，
不是消费者激活后的正常 client id。这是"不像零售版"的最硬证据。

### 6. 硬件实测（I2C 扫描，比 datasheet 可信）

```
I2C0 (SDA47/SCL48): 0x14 0x18 0x21 0x51
I2C1 (SDA39/SCL38): 0x53
```

| 地址 | 器件 | 用途 |
|---|---|---|
| 0x14 | ES7243E | 麦克风 ADC ✅ 在位 |
| 0x18 | ES8311 | 喇叭 DAC ✅ 在位 |
| 0x21 | PCA9535 | 电源/按键扩展 ✅ |
| 0x51 | PCF8563 | RTC ✅ |
| 0x53 | CHSC6x | 触摸 ✅ |

## 结论

1. **板型确认**：sensecap-watcher，不是别的变种。
2. **外设齐全**：音频输入输出、电源扩展、RTC、触摸全部应答。
3. **身份异常**：`ID_test` + `cal_*` → 这台更像**测试/标定单元**，而不是零售激活单元。
   这解释了"买到的不像可开发版"的感觉，但**不改变硬件能力**。
4. **唯一还没验证的**：摄像头（Himax HX6538）。它挂在 SPI2 + 要先用扩展器给 AI 芯片上电，
   不在 I2C 扫描范围内，所以上面这些证据证明不了它在不在。

## 下一步（把最后一个未知项钉死）

能读到协议回复就说明摄像头模组在位，读不到就是空贴。这个探测 30 行代码，一次烧写见分晓。
