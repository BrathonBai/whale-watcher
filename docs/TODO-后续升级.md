## 0. 基线（2026-11-01 实测，不是估算）

| 指标 | 实测值 | 出处 |
|---|---|---|
| 音频链路吞吐 | **59.5 KB/s**（10:56）→ **30.4 KB/s**（13:48） | 串口 `音频头 → 收尾` |
| PCM 需求 | 24000 × 16 bit × 1 ch = **48 KB/s** | `audio.cc` |
| 包丢失 / RTT（PC→设备） | 32 B：丢 10%、RTT 12–582 ms；1400 B：丢 0%、RTT 12–356 ms | `ping` 各 20 发 |
| TCP 窗口 | `WND=32768` `SND_BUF=32768` `MSS=1440` | `sdkconfig` |
| WiFi RX 缓冲 | `STATIC_RX=10` `DYNAMIC_RX=32` `RX_BA_WIN=6` | `sdkconfig` |
| 设备环缓 | 12 s（24000×12 采样） | `audio.cc` |
| 首次合成延迟 | Breeze 整段 WAV **5.3–6.1 s**；命中缓存 **0 s** | `/say` + 直连 curl |
| Breeze `/stream` | **当前不可用**：一次只吐 156 B 卡死，一次 25 s 超时 | 14:00 实测 |
| ASR | 常驻 SenseVoice，2 s 音频 **1.2 s** 出字 | `asr_server.py` 直跑 |
| 摄像头 | 240×240 JPEG，**5–6 KB/张**，周期采集 **约 9.5 s 一张** | 串口 + `/events` |
| TTS 引擎 | `breeze`（大肥鱼 voc_8yud7hz7c9q2），`breezeStream=false` | `/api/state` |

**一句话结论**：设备算力、缓存、编码都不是瓶颈；瓶颈是 **2.4 GHz 空口丢包**（30 KB/s < 48 KB/s）。音色问题已解决（breeze key 恢复）。

## P1 · 语音链路（音质与可听性）

### P1-1 Breeze `/stream` 探活 + 明确降级

- 现状：`breezeStream=false` 走整段（首音 5–6 s）；`/stream` 端点今天不可用。
- 要做：
  1. 启动时与每 N 分钟对 `/stream` 做 **500 ms 探活**，可用才用流式；
  2. 失败**显式降级**并打日志（不许静默换音色——历史教训见故障手册 §2）；
  3. `/api/state.tts` 增加 `streamOk / lastStreamError`。
- 验收：人为断网 → `state.tts.streamOk=false` 且日志有 `stream 不可用，降级整段`；恢复后自动回。

### P1-2 逐句合成 + 边播边合成

- 现状：整段合完才发（5–6 s 才开口）。
- 要做：按标点切句 → 第 1 句合成完立刻 `audioHead` 起播，后续句子并行合成；
  句子之间做 100 ms 静音垫，避免拼接破音。
- 验收：20 字回复首音 < 1.5 s；句子边界无爆音（`tts-smoke` 逐帧校验奇偶与长度）。

### P1-3 编码升级（治本）

| 方案 | 带宽 | 工作量 | 何时做 |
|---|---|---|---|
| 16 kHz 单声道 | 32 KB/s | 1 h（改 `audio.cc` + 桥重采样） | 只算缓解，仍偏紧 |
| **Opus 16–24 kbps** | **2–3 KB/s** | 1–2 天（设备加解码器） | **推荐**，空口再堵也无所谓 |

- 验收（Opus）：同一句话从 559 KB 降到 ~40 KB；30 KB/s 链路下 `缓冲积压` 始终 > 2 s。

### P1-4 设备本地播放（TF 卡 WAV）

- 依据 `音频本地播放-可行性-2026-11-01.md`：v2 **没实现 `SdInit()`**，照抄 v1 `board_watcher.cc:772`。
- 要做：`SdInit()`（上电复位 + 只挂一次）→ `audio_file.cc`（背压 + 打断）→ 协议 `play` → 桥 `/api/play`。
- 验收：`SD: 挂载成功` + `clip 就绪 9/9`；拔掉路由器仍能播；播放中按键 300 ms 内停。

### P1-5 宿主机出声开关（方案 C 落成配置）

- 要做：`audioOut: "device" | "host"`。`host` 时不下发 PCM，只发 `say`（字幕 + 表情），PC 本地放。
- 验收：切 `host` 后设备零音频流量，字幕与表情照常；一场演示 30 分钟无断续。

## P4 · 工程化与运维（最容易再踩的坑）

### P4-1 配置分层必须可见

问题：`插件的 cordis.patch.yml` > `config.json` > 默认值，**静默覆盖**。
今天 `maxReplyChars` 设 60 无效就是被 patch 层 240 盖住。

要做：
1. 启动时打印**每一项最终值 + 来源层**（patch / file / default）；
2. `/api/config` 写入后回读并提示「被 patch 覆盖，需改 patch」；
3. 文档里写清哪层改什么（音色/key/长度 → patch）。

验收：改 `config.json` 一项被覆盖时，日志明确出现 `xxx 被 patch 层覆盖（240）`。

### P4-2 密钥与降级

问题：`breezeApiKey` 明文在 `config.json`；key 失效时**静默落到 SAPI**，表现为「音色变了」，浪费了半小时。

要做：
1. key 挪到环境变量 / Windows 凭据管理器，`config.json` 只存引用；
2. 启动与每次合成前校验，失败**显式报错**（`state.tts.lastError`），不换音色；
3. 演示前一条命令体检 key。

### P4-3 日志落盘

现在 `logFile` 为空，日志只在 DSH 控制台，事后无法复盘。
要做：默认写 `<plugins-data>/logs/bridge-YYYYMMDD.log`，单文件 5 MB 滚动，`/api/state` 回显路径。

### P4-4 `/api/diag` 诊断端点

一次返回：设备在线/连接时长/计数器、tts 引擎与最近错误、最近 10 条下行（类型/字节/耗时）、链路自测结果。
验收：出问题时我只用这一个 URL 就能定位。

### P4-5 `tools/booth-check.ps1` 自检脚本

```
1) /api/state            → online / rejected / engine
2) ping 设备 20 发        → 丢包率、RTT
3) /say 固定句            → 首音延迟、下行字节
4) 串口（若有）           → 倍速 = (收尾-头)/秒数
5) 汇总一行：可用 / 降级 / 不可用
```

验收：一条命令 30 秒内给出「今天能不能上台」的结论。
