## 0. 先纠正一条旧结论（重要，省掉一次高风险操作）

移交清单里写着「`ota_1` 是空的 → 没有 A/B 双槽兜底 → 改固件前必须先改分区表」。
**前半句对，后半句错。** 刚才用 32MB 镜像解出真正的分区表：

```
label         type  sub   offset        size
nvsfactory    data   2    0x00009000    200K
nvs           data   2    0x0003b000    840K
otadata       data   0    0x0010d000      8K
phy_init      data   1    0x0010f000      4K
model         data 130    0x00110000    960K
ota_0         app   16    0x00200000     12M   ← 当前在跑（小智 1.8.5）
ota_1         app   17    0x00e00000     12M   ← 空槽，从未写入
```

- **两个 app 槽本来就在**，A/B 结构是齐的（`otadata` 记录 `ota_seq=1, state=VALID`，指向 `ota_0`）。
- 真正的风险不是"没有槽"，而是**刷机时绕过了 `otadata`**：直接往 `ota_0` 写、中途掉电 = 变砖。

**所以正确流程是（不需要改分区表）：**

```
1. 写空槽 ota_1（0xe00000），不碰 otadata   → 设备仍从 ota_0 正常启动
2. 写一条新的 otadata 记录指向 ota_1（seq+1, state=VALID）
3. 重启验证；不对就把 otadata 写回旧记录（旧记录已备份在 dump 的 0x10d000）
```

代价从"改分区表 + 全片重排 + 双槽验证"降成"写一个槽 + 一条 8KB 记录"。

## 2. 排序原则

1. **先消"白干风险"**：会让后面全部推倒重来的，排最前（架构形状、协议、备份可信）。
2. **能在 PC 上验的，绝不等到硬件**：UI V0.1 已经把运行时形状定死了——事件驱动、状态栈、局部重绘。这三件事错了，后面 UI、云、固件全要重写。
3. **动设备之前，先证明能救回来**：每一步刷机前 dump 对应区域，失败用 32MB 镜像恢复。
4. 硬件不在手上的（Cardputer、麦克风闭环）往后放。

### S1 · 内核骨架，先跑在 PC 上（1–2 天，不需要设备）

这是整份清单里最重要的一步。UI V0.1 已经把运行时形状定死了，先把它做成可运行的东西。

**进度：骨架已跑通（✅ 今天）**

```
firmware/
├── main/core/
│   ├── event.h          ✅ Event / Src / Topic 常量 + 前缀匹配
│   ├── event_bus.h/.cc  ✅ 前缀订阅 + 优先级派发 + 64 深度 SPSC 环（ISR 侧）
│   ├── ui_state.h/.cc   ✅ 9 屏状态机（含屏幕栈：notice/offline 覆盖、menu 推入）
│   └── dirty.h          ✅ 包围盒并集（坐标压缩，精确）+ 毫秒换算
└── host/
    ├── sim.cc           ✅ 四段场景驱动 + 每屏稳态预算表
    └── build.bat        ✅ VsDevCmd + cl /utf-8（不污染 PATH）
```

已跑出的结论（`firmware\host\build.bat` 一键复现）：

| 屏 | 每帧像素 | ms | 结论 |
|---|---|---|---|
| idle | 6,547 | 3.8 | 随便做 |
| menu | 6,067 | 3.5 | 随便做 |
| think | 14,164 | 8.2 | 可做 |
| say | 18,920 | 11.0 | 可做 |
| listen | 33,770 | 19.6 | 30fps 够 |
| speak | 39,331 | 22.8 | 30fps 够 |
| notice / offline | 0 | 0 | 静态 |
| 整屏切换 | 169,744 | 98.5 | ≈10fps，只用于换屏 |

> 顺带纠正了 UI 文档里「环带 1.7ms」的错误估算——真实是 19.6ms（差了 11 倍），
> 原因是径向条的包围盒占了整条环带，而不是细环。结论没变，但预算表换了。

**S1 剩余：**

1. `ui/backend_host.cc`：把原语画进 RGB565 framebuffer，导出 PPM/PNG，与 `design/out/*.png` 比像素；
2. `ui/backend_lvgl.cc`：设备后端（LVGL 对象 + 局部 invalidate）；
3. `ui/primitives.h`：ring/arc/bars/text/glow 的统一定义（两端共用）。

**验收（可回放）：**

1. `sim.exe` 八幕全过，任一幕脏区超预算即失败；
2. 导出 `frames\idle.ppm` 与 `design/out/idle.png` 平均色差 < 3%；
3. 状态机覆盖全部迁移（含 notice 3s 自动 pop、offline 覆盖一切、menu 旋钮环形遍历）。

### S2 · 协议单一事实源（0.5 天）

`proto/schema.json` 定义三类消息：`event`（设备→云）、`cmd`（云→设备）、`result`（设备→云）。
生成 `proto/gen/proto.h` 与 `proto/gen/proto.py`，**浏览器原型也改成说这套协议**——
从此原型不是"参考图"，而是设备端的镜像，可以用它测云端。

**验收：** 用 schema 生成的头/模块编译通过；原型通过 WebSocket 连接 `cloud/server.py`，收发的每条消息都能被 schema 校验。

### S3 · 云端最小闭环（1–2 天，可与 S1 并行）

```
cloud/
├── server.py     WS 接入 + 会话
├── pipeline.py   VAD → ASR → LLM → TTS 的流式骨架（先全用假实现）
├── fake.py       假 LLM（回固定文本）、假 TTS（正弦波 PCM）
└── policy.py     云侧预检
```

**验收：** 在浏览器原型里按一下「说一句话」，服务端收到事件、回三段文本、屏幕依次进 `think → speak`，
端到端延迟打印出来（目标 <500ms，本地假实现应该 <50ms）。

> 这是本周最想要的 demo：**V0.1 界面被真实云端驱动**，不是按钮切状态。

---

### S4 · 真机 bring-up（2–3 天，设备已在手）

只做四件事，不碰音频、不碰摄像头：

1. `esp_lcd` 点亮 412×412（先画纯色 + 十字）；
2. 旋钮（编码器 A41/B42，PCNT 或 GPIO 中断）；
3. 触摸（I2C1 39/38，SPD2010）；
4. idle 态跑起来。

**刷机纪律（每条都必须做到）：**

- 写 `ota_1`（空槽），不碰 `ota_0`；
- 每次写入前 `read_flash` 备份该区域；
- 收尾一律 `--after hard_reset`（上次就是漏了这条，设备停在下载模式看起来像砖）；
- 失败恢复：`esptool write_flash 0x0 backup\full_flash_32MB.bin`（约 15 分钟）。

**验收：** 真机 idle 态截图与 `design/out/idle.png` 平均色差 < 5%（拍照允许透视误差）；
旋钮能进菜单并切换 6 项。

### S5 · 语音闭环（3–5 天）

I2S 采集 → esp-sr VAD → Opus 16k → WS 上行 → ASR → LLM → TTS → 24k 播放，
加 barge-in（本地能量门抢断）。这一环最容易超期，前面 S3 的假实现就是为它铺路。

**验收：** 说"看下桌上有什么" → 设备拍照 → 云端 VLM → 念出答案；播放中喊"停"，300ms 内静音。

### S6 · Cardputer 第二身体（等板子上手）

拉 M5Stack 官方 BSP 核引脚（键盘矩阵、BMI270 I2C、ST7789），同源 `core/` + `ui/` 跑起来，
ESP-NOW 互通。**横屏布局另做一套**（径向造型在 240×135 上不好看，改横向电平条 + 左侧状态点）。

### S7 · Hub 能力描述符 + 反射弧（可随时插队）

SD 卡放一个 `cap_*.json` → 屏上自动多一个事件态、云端自动多一个工具。
这是"新轮子"和"小智"的分水岭，但它依赖 S1 的注册表抽象，所以排在后面。
