# 设备本地放音频：可行性与做法（2026-11-01 凌晨）

> 结论先给：**能，而且不需要 MP3 解码器。**
> 用 TF 卡放 24 kHz / 16 bit / 单声道 WAV，复用现有 I2S 与 12 秒环形缓冲，约 **3–4 小时**（含刷机实测）。
> 但**今晚不要动固件**：设备不在线，改完没法验；摊位先用「电脑出声 + 设备做表情字幕」兜底。
> 本文只写方案，不改任何代码。

---

## 1. 为什么现在会卡（先把责任分清）

| 事实 | 数值 | 出处 |
|---|---|---|
| PCM 带宽需求 | 24 000 × 16 bit × 1 ch = **48 KB/s** | `audio.cc` / `kRate` |
| 实测链路 | **21–28 KB/s**（0.45–0.6 倍实时） | 故障手册 §12 |
| 设备缓冲 | **12 s** 环形（24 000 × 12 采样，约 960 KB PSRAM） | `audio.cc` `kRingSamples` |
| 起播预缓冲 | 1000 ms，起播领先 896–1072 ms | 故障手册 §11 |
| 帧间隔形状 | 200 / 400 / 800 / 1600 ms 阶梯 | TCP 重传退避，不是设备慢 |

**结论：不是缓存小，是管道窄。** 12 秒缓冲从没被填满过；数据生成得再快，也快不过 48 KB/s 的硬需求。
所以「换大缓存 / 加内存」都不是解；要么把码率降下来（Opus / 16 kHz），要么**别走网络**（本地文件）。

已排除的省电因素：`net_wifi.cc` 已经 `WIFI_PS_NONE`，`ws_client.cc` 已经 `TCP_NODELAY`。
所以 21–28 KB/s 就是当前 AP / 干扰下的真实吞吐，不是配置漏了。

## 2. 三条路，按「今晚能不能用」排序

| | 做法 | 工作量 | 风险 | 适合 |
|---|---|---|---|---|
| **C** | 电脑接音箱出声；设备只负责表情 + 字幕 | 0（或桥加 30 行 host 播放） | 低 | **今晚 / 现场兜底** |
| **A** | TF 卡放 WAV，设备本地播放（推荐的正解） | 3–4 h | 中低 | 路演后；或今晚有 4 h 且设备在手 |
| **B** | TF 卡放 MP3，固件里塞解码器 | A + 2–3 h | 中 | 要放 BGM / 几十条长音频 |

MP3 不是不能做，是**不划算**：卡是 GB 级，5 秒 WAV 才 240 KB，100 条语音 24 MB；
为省这点空间引入解码器 + 重采样（MP3 多为 44.1 kHz，要转 24 kHz）不划算。
真要放背景音乐，再上 MP3（minimp3 单头文件，约 60 KB flash，S3 解码余量很大）。

## 3. 方案 A：TF 卡本地放 WAV（推荐）

### 3.1 先补一个洞：v2 根本没挂 TF 卡

- `board_watcher.h:92` 声明了 `SdInit()` / `SdReady()`，但 **`main/` 里没有实现、也没有调用**（全局搜 `SdInit` 只有声明）。
- 所以 `clip_player` 读 `/sdcard/anim/*.bin` 永远失败，只有固件内嵌的 3 段动画能播——
  这也解释了 v2 交接里写的「三段动画」而不是卡上的 9 段。
- **v1 里有现成实现**：`firmware/device/main/board_watcher.cc:772` 的 `SdInit()`，照抄即可（30 分钟）。
  它比 BSP 的 `bsp_sdcard_init_default()` 多两件关键的事，别省：

  1. **给卡做一次上电复位**：PCA9535 在 ESP 复位后**保留输出**，热插卡 + 软复位时卡的电从没断过，
     会停在未定义状态（现象：CMD8/CMD2 回 `0x108`）。做法是把 `PWR_SDCARD` 拉低 300 ms 再拉高。
  2. **只挂一次，不重试**：每失败一次 `esp_vfs_fat_sdspi_mount` 都会留下 FATFS 结构，
     实测三次重试把内部堆最大连续块吃到 1536 B，`ui` / `ws` 任务静默创建失败——画面定死、WS 连不上。

  FATFS 已开（`CONFIG_FATFS_VOLUME_COUNT=2`、`CONFIG_FATFS_SECTOR_4096=y`），
  SDSPI 引脚：CLK=4 / MOSI=5 / MISO=6 / CS=46（`board_watcher.h:90`）。

**验收**：串口出现 `SD: 挂载成功`，`clip 就绪 9/9`（卡上的 9 段动画也会一起回来）。

### 3.2 播放器（约 120 行）

复用现成的音频通道，不碰解码器：

```cpp
// audio_file.cc —— 从 /sdcard 读 24k/16bit/mono WAV，喂进现有环形缓冲
bool PlayFile(const char* path, bool loop);   // 打开 → 校验 RIFF/WAVE/fmt → 起任务
void StopFile();                              // 置停止位，任务退出后关文件

// 任务循环（优先级 5–6，低于音频 7、高于渲染 4）：
//   read 4 KB → 若 StreamBuffered() > 8 s 就等 20 ms（背压）
//             → audio::StreamWrite(buf, n/2)
//   EOF：loop ? rewind : 退出
```

要点：
- **必须做背压**：直接 `StreamWrite` 到满会丢采样；`StreamBuffered()` 是现成的。
- **打断**：收到新的 TTS 或按键时先 `StopFile()`，否则两路声音混在一起。
- **只接受 24k/16/mono**：格式不对就拒绝并打日志，别做隐式重采样。
- 头 120 ms / 尾 180 ms 的静音垫可以沿用（防削波）。

### 3.3 协议与桥（各几十行）

- 固件：`proto.cc` 加一种下行 `{"t":"play","file":"/sdcard/voice/hello.wav","loop":0}`，`app_ui.cc` 分发。
  ⚠️ 这会改**协议契约**：`bridge/lib/contract.js` → `docs/协议-v2-契约.md` 是生成的，`contract.test.mjs` 会比对，三处要一起改。
- 桥：`POST /api/play`（或 `device_play` 工具）→ 下发上面的 JSON；再加一个「停」。
- 生成：`tts_breeze.js` 已经支持 `output_format=wav`（故障手册 §2.1），写个 `tools/gen-voicepack.mjs`
  把台词表逐条合成到 `E:\voice\*.wav`，拷进卡里 `/sdcard/voice/` 即可。

### 3.4 验收（缺一不可）

1. 串口：`SD: 挂载成功 30436 MB` + `clip 就绪 9/9`。
2. `/api/play` 后串口：`play: hello.wav 3.2 s`，喇叭出声，**与网络无关**（拔掉路由器也照放）。
3. 播放中按旋钮：300 ms 内停（对齐你原来给「可打断」定的验收）。
4. 连续放 20 条不重启、不爆音。

## 4. 方案 C：今晚就能用的兜底

**声音从电脑出，设备只做表情 + 字幕。** 现场最稳，零固件风险。

- 电脑接一个有线/USB 音箱（**别用蓝牙**：蓝牙也在 2.4 GHz，场馆里一样堵）。
- 音箱放在设备后面或桌子下方，观众看到的是「她在说话」，听到的是同一个音色。
- 桥侧要加一个开关（约 30 行）：`audioOut: "host"` 时本地播放、不下发 PCM；
  只发 `say`（文本 + 表情）给设备。**这个改动今晚可以做，也可以纯手工**：
  把设备音量调到 0，另开一个进程念同一段文本（音色会不一致，仅作最后兜底）。

> 为什么这条最稳：设备与电脑之间只剩 `say` / `face` 几百字节的 JSON，
> 2.4 GHz 再堵也堵不死；声音走本地声卡，和 WiFi 完全解耦。

## 5. 摊位网络与供电（到场先做这 5 件事）

1. **量链路**：`POST http://127.0.0.1:7788/api/linktest?seconds=3`，串口看 `音频头 → 收尾` 的耗时 ÷ 3。
   - ≥ 1.2 倍速 → 设备出声可用；
   - 0.5–1.0 → 就是这里，切方案 C；
   - 越接近 0.5，越不要在现场改代码。
2. **自带热点**：手机开 2.4 GHz 热点，现场扫一下信道，选 1 / 6 / 11 里最空的；
   设备与热点放在桌子同一侧，别隔着人。
3. **别用场馆 AP**：几百人连同一台 AP，2.4 GHz 的空口时间根本轮不到你。
4. **供电**：插 5V 2A；400 mAh 电池大约只撑 1 小时，别用它撑全场。
5. **兜底顺序**：本地 WAV（若做了）→ 设备短句 TTS → 电脑音箱 + 设备表情 → 录屏。

## 6. 如果只有 4 小时，怎么排

| 时间 | 做什么 | 判定 |
|---|---|---|
| 0:00–0:30 | 写 `SdInit()`，只验证「挂载 + 9/9 动画」 | 串口出现 9/9 才继续 |
| 0:30–1:30 | `audio_file.cc` + 一条测试 WAV 循环播放 | 拔网线仍出声 |
| 1:30–2:30 | 协议 `play` + 桥 `/api/play` + 契约三处同步 | `contract.test.mjs` 绿 |
| 2:30–3:30 | 刷机、20 条连播、按键打断 | 4 条验收全过 |
| 3:30–4:00 | 生成路演台词包，拷卡，彩排一遍 | 不重启、不爆音 |

**红线**：任何一步在会场做不完，就退回方案 C，不要带着半成品固件上台。

## 7. 一句话回答「能不能塞 MP3」

能。ESP32-S3 跑 minimp3 绰绰有余，32 MB flash 也放得下。
但你要解决的是「别走 WiFi」，不是「MP3」——**WAV 直出更短、更稳、音质一样**；
MP3 等路演结束、要做 BGM 或多语言语音包时再上。
