| 项 | 之前 | 之后 | 说明 |

## 4. 协议（跨线约定，字段名不要改）

### 4.1 设备 hello（每次连上都发）

```json
{"t":"hello","fw":"hub_v2","board":"watcher","ver":"0.2","cam":1,"w":240,"h":240,
 "codecs":["pcm","opus"],"opusRate":16000}
```

- 解码器不可用（PSRAM 预检失败/创建失败/任务创建失败）时：`"codecs":["pcm"]`，**不带** `opusRate`。
- 老桥忽略未知字段；老设备没有这些字段，桥按 pcm 处理。
- 实现：`proto::BuildHello(out, cap, opus_available)`（身份常量集中在 `proto.h`，修掉审计 FW-22 的"两套 hello"漂移）。

### 4.2 下行 audio 头

| 字段 | opus | pcm（缺省/老桥） |
| --- | --- | --- |
| `codec` | `"opus"` | `"pcm"` 或不带（缺省=pcm） |
| 二进制帧 | **每 WS 二进制帧 = 一个裸 Opus 包**：20 ms / 16 kHz mono / 无长度前缀 / 1–1275 B（长度可奇可偶） | 裸 PCM，24 kHz/16 bit/mono，帧字节数应为偶数 |
| `rate` | 24000（解码输出率）；也容忍 16000 | 24000（校验 1..48000 保持原宽范围） |
| `bits`/`ch` | 16 / 1（强制校验） | 16 / 1（强制校验） |
| `bytes` | 可为 0（设备不对账字节数） | 声明总字节数（用于丢帧对账） |
| `seq` | 每段递增，`audio_end` 配对 | 同 |

设备侧校验（`proto.cc`）：`codec` 只接受 `"opus"/"pcm"`，未知值**整条拒掉**（不按 pcm 播 opus
字节，避免满耳噪音）；opus 的 `rate` 只接受 16000/24000。设备不做任何重采样（libopus 内部
16k→24k 重采样由解码器完成）。

### 4.3 上行 pong（ping 的回复）

```json
{"t":"pong","bufMs":312,"underruns":0,"reconnects":1,"rssi":-52,"codec":"opus"}
```

| 字段 | 语义 |
| --- | --- |
| `bufMs` | 当前 PCM 环形缓冲积压毫秒数 = `audio::StreamBuffered()*1000/24000`（0..2500） |
| `underruns` | 累计欠载次数（**只在 audio 头→audio_end 的"期望播放"期间**统计环空的沿；空闲不算） |
| `reconnects` | WS 重连次数（`ws::Stats.reconnects`） |
| `rssi` | WiFi RSSI dBm（未连上为 0；负值是正常 dBm） |
| `codec` | 当前下行编码 `"pcm"/"opus"`（最近一段 audio 头决定） |

pong 在 WS 收包任务上下文组装（只读计数器 + 发一帧短文本），不阻塞收包。

## 5. 失败与回退（不静默）

1. **启动**：`audio::StreamInit()` 之后调 `audio_dec::Init()`：
   - PSRAM 可用 < **320 KB** 预检失败 → ERROR，回退 PCM；
   - 包环/解码缓冲/锁/解码器/任务任一创建失败 → ERROR，回退 PCM；
   - 回退后 `s_opus_ok=false` → hello 只报 `["pcm"]`，桥侧不会发 opus。
2. **运行期**：桥仍发 opus 但解码器不可用 → `audio` 头处理里 **ERROR**（"本段无声；检查
   hello.codecs 与桥侧配置"），二进制帧走 `PushPacket` 被拒（计数 + 限频 ERROR），
   `audio_end` 的统计行会给出累计丢包/解码失败数，绝不静默。
3. **包环满/忙/非法长度**：丢包 + `dropped` 计数 + 限频 ERROR（第 1 次、每 50 次）。
4. **解码失败**：`decode_errors` + 限频 ERROR（带 `opus_strerror`）。
5. **PCM 环满**：`write_drops` 累计，每丢满 1 秒量打一行 WARN（解码任务不阻塞）。
6. **PCM 路径完全保留**：`codec` 缺省即 pcm，原奇偶字节兜底/seq 对账/垫音逻辑不变；
   老桥 + 新固件 = 走原路径。

## 6. 需要 Lead 合并的 sdkconfig.defaults 行

以下选项在 esp32s3 上**都是 Kconfig 默认值**（不加也能编/能跑），但显式固定可防止将来
改目标/关默认时静默漂移（尤其伪栈大小和 PSRAM 偏好），建议合入：

```ini
# ---- micro-opus / Opus 下行解码（2026-11-03，vendored 组件 components/micro-opus）----
CONFIG_OPUS_THREADSAFE_PSEUDOSTACK=y
CONFIG_OPUS_PSEUDOSTACK_SIZE=120000
CONFIG_OPUS_STATE_PREFER_PSRAM=y
CONFIG_OPUS_PSEUDOSTACK_PREFER_PSRAM=y
CONFIG_OPUS_OGG_DECODER_PREFER_PSRAM=y
CONFIG_OPUS_FLOATING_POINT=y
CONFIG_OPUS_ENABLE_XTENSA_OPTIMIZATIONS=y
```

说明：

- `CONFIG_FREERTOS_TLSP_DELETION_CALLBACKS` 由组件 Kconfig `select` 自动置 y（IDF 默认也是 y），不必手写。
- 我们只有一个任务用 Opus（`adec`），线程安全伪栈每线程 120 KB 即"总共 120 KB"；
  若以后想省 PSRAM，可改 `OPUS_NONTHREADSAFE_PSEUDOSTACK`（单全局伪栈，但多任务并发会崩，**不建议**）。
- 若 PSRAM 吃紧，可把 `CONFIG_OPUS_PSEUDOSTACK_SIZE` 降到 60000（组件允许下限），但**必须真机
  验证**是否触发 `pseudostack overflow`（该错误会 `abort`，不是返回错误码）。

## 7. 编译注意事项（给 Lead）

1. **必须先同步组件目录**：`firmware-v2/components/` 被仓库 `.gitignore` 排除（和其它 vendored
   组件一致），构建副本 `%LOCALAPPDATA%\hubdev\v2` 里必须存在
   `components/micro-opus/`（含 `lib/opus`、`patches`、`cmake`），否则会报
   `Failed to resolve component 'micro-opus'`。
2. **构建机需要 `git`（不是 `patch`）**：本仓库把组件的 staging 补丁应用方式改成了
   `git apply --recount --binary`（原版用外部 GNU patch）。原因：①上游 0.4.1 的 patch 文件
   被空白裁剪过（空上下文行丢行首空格、末尾上下文截断），GNU patch 能容忍但严格实现报
   corrupt；②Windows 默认无 patch.exe，Git 自带的 MSYS2 patch 在受限沙箱里会因 signal pipe
   失败直接崩溃（Win32 error 5）；③`git apply --recount` 按实际行数重算，IDF 环境必有 git。
   已在 CMake 配置层做过端到端验证（见 §8）。找不到 git 时 CMake 报
   `Opus: 'git' command not found`。
3. **首次 configure 会慢一些**：要把 `lib/opus`（约 3.6 MB）复制到
   `<build>/esp-idf/micro-opus/opus-staged/` 并用 `git apply` 打 6 个补丁（core + Xtensa），
   本机实测约 3 秒；之后靠 `.staging_complete` 标记跳过。改 `sdkconfig` 里 `CONFIG_OPUS_*`
   会触发重新 staging（正常）。
4. 组件会把**编码器+解码器+Ogg 容器**整体编译：flash 会明显变大（预估 +300–500 KB），
   分区 12 MB 够用。本轮没裁组件源码（怕动 `sources.cmake` 引入构建风险）；如果以后
   flash 紧张，可只留 decoder 源 + 去掉 `micro-ogg-demuxer`，属于后续优化。
5. 主组件 `REQUIRES` 已加 `micro-opus`（主组件通过其 public include 目录拿到 `opus.h`）。
6. 本轮**没有**改 `sdkconfig.defaults`（归 Lead 统一合并，见 §6），也没改
   `net_wifi/app_main/render/camera/partitions/bridge`。
7. 若出现与 Opus 无关的编译错误，那属于另一条固件线（app_main/net_wifi/render 等）的并行改动。

## 9. 未验证项（必须真机/联调才能确认）

1. **真机音质/延迟**：16 kHz 裸包 → libopus 内部重采样到 24 kHz 的实际听感；20 ms 包间隔
   下 `bufMs` 稳态是否稳定（预期 200–600 ms）。
2. **CPU**：组件宣称 SILK 解码 ~2% CPU（48k 立体声）；本机 24k 单声道应更低，但未实测
   `adec` 任务占用（可看 `uxTaskGetStackHighWaterMark` / 逻辑分析仪）。
3. **PSRAM 伪栈**：首次 `opus_decode` 时懒分配 120 KB；若失败 libopus 会 `celt_fatal`→`abort`
   （Init 的 320 KB 预检只能降低概率，不能完全消除碎片化风险）。失败表现会是设备重启，
   日志 `pseudostack overflow`。
4. **WS 任务里的 `Flush()` 最坏阻塞**：理论上限 2 s，正常 <150 ms（解码远快于实时）；但
   桥若一次性灌满 64 包（突发发送）再发 `audio_end`，Flush 会占住收包任务到解完为止。
   现场若出现 pong 延迟/断连，先看 `音频收尾（opus）` 日志的残留包数。
5. **2.5 s 缓冲余量**：12 s→2.5 s 后，若 WiFi 断流 >2.5 s 会直接丢音频（旧版能扛 12 s）。
   会场 WiFi 下的实际断流时长需实测；这是本轮有意的内存/延迟取舍。
6. **桥侧协商**：hello 的 `codecs/opusRate` 与 pong 的 `bufMs/underruns/reconnects/rssi/codec`
   要等桥线合入后联调；本线只保证设备侧按契约发。
7. **underrun 语义与自适应阈值**：设备只在"期望播放"期间计欠载（每段音频每个空档记 1 次），
   桥侧自适应算法的阈值需按这个语义标定。
8. **`audio` 头 codec 混用/切换**：契约要求每段固定；设备允许逐段切换（按头覆盖），
   但桥若在句子中间切换编码，设备会按新 codec 解释后续二进制帧（未做逐帧校验）。
9. **libopus 版本**：组件包内未携带 `package_version`（`NEWS` 为空），无法从包内读出上游
   版本号；升级组件时以微组件版本为准（见 `VENDORED.md`）。
10. **flash 实际增量**：以 Lead 的 build `size` 输出为准。
11. **完整 `idf.py build` 未在本机执行**（本机不能构建）：组件 staging 只在 CMake 配置层
    验证过（git apply 6 补丁 + 142 个 staged 源文件 xtensa `-fsyntax-only` 全过）；剩余风险
    主要是 IDF 组件注册/链接细节（`idf_component_register` 的 include 传播、`add_subdirectory`
    的 micro-ogg 子目标、链接期符号），首次 build 若报错请把完整错误行回传本线。

## 10. 验收方法（刷机后看日志）

- 启动：`adec: Opus 解码就绪：16000 Hz 裸包 → 24000 Hz/16bit/mono；包队列 64×1275 B = 79.7 KB，解码缓冲 5.6 KB，PSRAM 可用 …`
  失败则 `adec: …失败：回退 PCM` + `ui2: 交互就绪：…；下行编码=pcm（Opus 已回退）`。
- 连上桥：`ui2: 已发 hello（codecs=pcm+opus）`（桥日志应能看到 `codecs:["pcm","opus"]`）。
- 每次 TTS：`ui2: 音频头：seq=N codec=opus rate=24000 声明 0 字节` →
  `ui2: 音频收尾（opus）：M 包，包环残留 0，丢包 0，解码失败 0，写环丢采样 0`。
- pong：桥侧 `/api/diag` 或抓包应看到 `bufMs/underruns/reconnects/rssi/codec`。
- 回退演练：设备端很难人为让 PSRAM 不足；可在桥侧强制发 codec=pcm 验证 PCM 路径回归。
