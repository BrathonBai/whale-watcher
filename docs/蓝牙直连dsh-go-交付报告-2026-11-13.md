**真机暴露并已修掉的问题（都已回写源码+文档）**：
1. 原始顺序（WiFi→BLE→app_ui）下 `adec` 任务栈 / LED RMT 通道申请失败，BSP `ESP_ERROR_CHECK` abort → 重启循环。
   → 启动顺序改为 app_ui/UI 任务先于 link；`Auto` 改成 BLE 优先、失败才 WiFi（单栈）。
2. 无 TF 卡时 `mp3::Init` 在内部 RAM 白占 ~24 KB，BLE 运行期只剩 10.9 KB，`shot` 的 SSCMA SPI 队列失败。
   → 无卡跳过 mp3 初始化，内部 free 回到 34.7 KB，拍照恢复。
3. 连接瞬间发的 hello 在手机订阅通知前就丢了（桥要等 10 s 重发）。
   → 增加 `BLE_GAP_EVENT_SUBSCRIBE` 回调，手机打开 CCCD 后立刻补发 hello（实测 30 ms 内到达）。
4. `hello.ver` 从 0.2 升到 0.3（BLE/ADPCM 固件语义版本）。

**仍未在真机验证**：设备 mic→手机的大流量 voice 上行（需按键录音）；`>link wifi` 的 WiFi-PC 回归；

## 4. 实现要点（与契约的对应）

- **GATT**：Service `6a696e67-6a69-6e67-8000-000000000001`，DOWN `…0002`（write-no-response），UP `…0003`（notify）；
  设备名 `Jingjing-XXXX`；MTU 247；广播带 128-bit UUID。
- **分帧**：7 字节头（magic 0xA5 / type / flags / frag_index / frag_total / len LE16）；text≤4096、binary≤16384、
  最多 255 片；顺序重组 + 3 s 超时 + 丢包计数；无应用层 ACK（BLE 链路层重传 + 设备侧背压重试）。
- **音频**：IMA ADPCM 4:1，24 kHz→12041 B/s；块 1024 B（4 B 头 = 首采样 predictor + index）= 2041 采样 = 85.04 ms；
  末块短块用奇数采样，`samples` 字段裁掉补齐的 1 个采样；桥解码后写 WAV → ASR 不用改。
- **双链路仲裁**：`link::` 门面，`Auto|Ble|Wifi` 存 NVS；BLE 连上暂停 ws 会话，断开恢复；串口 `>link` 可强制。
- **手机注入**：不改运行时。App 启动引擎前把插件 assets 递归写到 PRoot `/opt/dsh-app/embodied/`，
  生成 `embodied.patch.yml`（含随机 `wsToken`、`host:127.0.0.1`、`discover:false`）并用 `--patch` 注入；
  安全模式不注入。`wsToken` 防止同机其它 App 连 127.0.0.1:7788 控制设备。
- **安全边界**：BLE 空口 v1 **不加密**（LE 配对/绑定留 v2，已在契约 §8 明示为已知限制，不是 bug）。

## 5. 关键决策与偏差记录

| 项 | 决策 | 原因 |
|---|---|---|
| ADPCM 块格式 | 1024 B / 2041 采样（不是最初写的 1024 采样/516 B） | 以 ffmpeg `adpcm_ima_wav -block_size 1024` 实测为准；桥解码与其逐采样一致 |
| `samples` 字段 | voice/audio 头新增可选字段 | 偶数末块会补 1 采样，需要精确裁掉；缺省不裁 = 老固件兼容 |
| S3 的 BLE 配置符号 | 用 `CONFIG_BT_CTRL_BLE_MAX_ACT` 等 S3 符号，spec §5.2 的 `BTDM_*` 是 ESP32 的 | 以 IDF 5.5 Kconfig 实际生效为准（构建通过） |
| 桥 TTS 在手机 | 无 ffmpeg → `audioCodec=auto` 选 ADPCM；TTS 引擎建议 Breeze key / 关 TTS；ASR 用引擎侧 speechToText | 手机 PRoot 不带 ffmpeg（上游运行时事实） |
| dsh-Go 集成方式 | guest 插件注入，不重建 1 GB 运行时 | 复用上游 `AppAuthGuest` 机制，最小侵入、可回滚 |
| Flutter 文案 | `embodied_strings.dart` 中英硬编码，不引 ARB 生成链 | 交付环境无 Flutter，无法跑 l10n_merge + gen-l10n；已标注「待迁 ARB」 |
| 通知文案 | Kotlin 内 zh/en 硬编码（`AppStrings.isEnglish`） | 同上；避免手改生成资源 |

## 8. 已知限制 / 未验证（汇总）

- **手机 App 已能编译/安装/真机跑通 BLE+桥**；但 **goldens、`flutter test` 未跑**，
  App 当前**未登录 DeepSeek 账号**（本次重装后需重新登录；对话/模型不可用），ASR 未就绪
  （设备语音上行未实测）。
- **当前安装是 debug 签名、官方包名**（旧官方 1.0.15 已按用户确认卸载）。以后要装官方
  release 包，签名不同无法 `install -r`，必须先卸载（会清数据）；可用你的 release key 重打
  一个同签名版本，或继续用这个 debug 包直到交付正式 release。
- **会话/工作区不跨主机同步**：dsh-Go 的对话属于「当前主机」，账号登录只解决模型鉴权；
  PC 与手机各自一套引擎会话不会自动互通。要互通需让手机连 PC 的「远程主机」（PC 装 DSH
  Remote 插件），Watcher 走 PC 大脑则需要桥可被手机经 LAN 访问（现有 `bridgeUrl` 可配置，
  但 token/防火墙/远程模式联动还未做）。
- **设备 mic→手机语音上行未实测**（需按设备键录音）；ADPCM 编码算法已用固件自检 + 桥 fixture 双向验证。
- **v0.4 已移除 WiFi**：设备不再有 WiFi/WS/桥地址代码与 `>link wifi`，只有 BLE；旧 WiFi 固件
  仅作回滚归档（§9）。`sdkconfig.defaults` 需保留 `CONFIG_I2C_SKIP_LEGACY_CONFLICT_CHECK=y`，
  否则基于全新 sdkconfig 的构建会在 global ctors 阶段 `i2c: CONFLICT!` 重启。
- **BLE 空口不加密**（v1 设计），附近设备可冒充手机；LE SC 绑定是 v2 项。
- **内存余量**：v0.4 BLE-only 运行期内部 free **119,215 B**（v0.3 为 34.7 KB），
  PSRAM free 6,673,160 B；后续加功能前仍建议先看 `[mem]`。
- **手机桥的 TTS/ASR**：正在切到 DeepSeek 官方 ASR/TTS（2026-11-13 发布，见 §10），
  旧 Breeze/Edge/SenseVoice 路径保留作回退；需要 `DEEPSEEK_API_KEY`（或插件配置）才能启用。
- **单设备单连接**；后台保活依赖前台服务 + 省电白名单（系统杀掉后靠引擎重启恢复）。
- `apply.sh` 未实测（本机 bash/WSL 不可用）；Windows 用 `apply.ps1`（已实测）。
- 手机 loopback 上任何 App 都能访问桥，`wsToken` 只防未授权访问，不防同机恶意 App 读 prefs（Android 应用沙箱边界内）。
